# Server-indexed surfaces and Room reads

- **Connected app activity requires pickup.** `show_dispatched_agent_work` queues Beeline-machine work; working status requires its live claimed generation. Rooms MCP members become working through their explicit tool pickup, sharing the command claim owner. Stored `pending:` placeholders never imply an active execution. The one-time `connected-app-placeholders-v1` cleanup removes legacy app placeholders, preserving real turns. Corner reports to a connected app supersede unhandled reports with the same recipient, sender, origin and status, keeping the newest text and recording `superseded_report`; a live claimed report retains its authority. Machine queues and reports originating outside corners retain their existing behavior. Coverage: `connected-app-activity.integration.test.ts` (`R1`); built report → phone-read proof: `node --import tsx scripts/prove-connected-app-activity.mjs`.

- **Answered private blockers cannot wake their commander later.** The report's durable `waitingAnswered` marker also fences pending report commands at delivery and claim, for each independent source. A live claimed report continues; unrelated commands survive. Coverage: `STALE-ANSWERED-REPORT` in `commander-wakes.integration.test.ts`; production trace and built HTTP proof: [answered report reproduction](answered-report-reproduction.md).
  A later private order from the report recipient to its author in the origin corner also answers a blocked/needs-decision report. This covers delegates who are not the primary implementer and therefore have no attention-index blocker (`STALE-DELEGATE-REPORT`).

- **Deliberate silence survives every harness.** `no_reply_needed` calls `markAgentTurnSilent` to persist `completion_kind='no-reply'` and end that selected command through `beeline_end_agent_turn`; later invocation diagnostics preserve it. `DaemonService` acknowledges and discards later final text for that turn before public insertion or private report routing, including the atomic reply path. Whole final silence declarations are no longer filtered: final text publishes as written, and the only silence path is the `no_reply_needed` tool call. The generation and cancellation authority checks still apply. Coverage: `agent-command.integration.test.ts` and `commander.integration.test.ts` (`Reproduction R1`). Queued files drain through the ordinary reply writer before explicit silence is recorded; files attach to an existing same-turn post or form a file-only message. A report wake whose automatic inherited report is skipped falls through to public reply delivery instead of discarding prose and files. Closing prose after an explicit post to the same place and turn generation is retained as a Turn summary activity note, rather than a second conversation message; posts elsewhere do not suppress it.

- **Voice uses existing agent identities and ordinary orders.** `apps/server/src/voice-service.ts` owns membership and dispatch; `voice-room-runtime.ts` speaks command-provenance reports without capping real work. Short-press dictation remains separate. Providers, native runtime requirements and isolated proof commands: [voice mode](voice-mode.md).

- **Computer activity is an observation, never an owed reply.** `computer-session.ts` retains Squire's preview channel, HTML and latest frame while any viewer remains; `ComputerSessionCard` preserves that preview's token when opening the full view. `agent-command.ts` coalesces one pending observation per share behind other work and refreshes its source at claim; Room/corner turn loops accept silence, and connection loss never creates a failure notice or a new command. Coverage: `computer-session.test.ts`, `server-command-intake.test.ts`, and the Room/corner turn tests.
- **Shared browser links enter through Beeline.** Point people at the live browser card. `browser_share start` returns its message id as `cardId`, its source session id for ending the share, and a plain instruction to open the card posted in this place. It returns no URL; the raw `/s/<id>/` address offers web and app entry without disclosing session metadata. The app obtains a viewer token with `openComputerSession` after sign-in. Tokens and current Room/agent authority still gate the viewer.
- **Computer share upstreams are allowlisted.** The server fetches and tunnels to a share's upstream URL, so `createComputerSession` accepts only `body:` or an `https:` URL whose host is under `*.trycloudflare.com`, the host Squire `operate_share` returns. IP literals, `localhost` and `.localhost`/`.internal`/`.local` hosts fail. Coverage: `computer-session.test.ts`.

- **Plain reads retain complete results.** Needs You reads/counts include every qualifying question, including beyond 500. Scheduled Work reads and public webhook metadata follow active Room membership (`subscription-webhooks.ts`); mutations and secret token controls retain management authority. Net result codecs validate structure without whole-result byte/node quotas; input limits remain. Proofs: `read-surface-growth.postgres.test.ts` and `packages/net/src/read-surface-growth.test.ts`.

- **Server-indexed surfaces own durable answers.** `phone-service.ts` owns paint-ready queries; `packages/api-contract/src/phone.ts` owns DTOs. Screens send ordinary operations through `live-connection.ts` and render validated responses. `server-read-owner.ts` retains the existing list/Tray caches and plain live-delta updates; `surface-boundary.test.ts` protects their cache writes. No read capability or family negotiation is required.
- **A Room GET does not carry child corners.** `PhoneService.readRoom`/`RoomView` stop at the Room; corners come from `RoomViewClient.corners`, and the chat list's `cornerCount`/`openCorners` feeds `DesktopRoomCorners`. Opening a Room makes one live subscription (`useRoomSurfaceSession`); never expand watch-filter keys into per-corner subscribes.
- **A Room payload is projected, never all-or-nothing.** `readRoomView` (`phone-guards.ts`) fails only on a missing `room.id` or `messages`; unreadable optional fields are absent, never invented; unknown `role` reads `member`; `repositoryResolution` reads `unverified`.
- **One terminal owner.** `beeline_end_agent_turn` in `agent-turn-end.ts` is the only command/turn terminal writer. Replies, receipts, explicit Stop, archival and workflow cancellation call it in their authority transaction. Generation fencing and terminal idempotence preserve the first result; final usage and diagnostics may arrive afterward. The architecture check has zero allowance for other writers, including terminal inserts. Coverage: `agent-turn-end.test.ts`, `agent-turn-lifecycle.test.ts`, and the planted guard tests in `scripts/architecture-invariants.test.mjs`.
- **Composer status is server-owned.** `RoomView.pendingAgentCommands` and the send acknowledgement show accepted human work waiting for claim. Claim binds its working generation to the authenticated machine connection. An answer or explicit terminal receipt ends it; connection closure returns unfinished commands to pending for the next connection. Neither command age nor missing receipts expire or resend a turn. Connection bootstrap reads canonical pending member Rooms without mutating or re-nudging those commands. Optimistic turns do not prove presence. Room `agentState` includes its open corners (`CHAT_LIST_SQL`). Stop remains available to anyone authorized to act in the Room (`cancelAgentTurn`, `TurnProgressLine.tsx`). External sends carry `externalAgentHandles` from the stored MCP mentions in `phone/mention-notices.ts`; the shared thinking line renders a static, single-line ellipsis acknowledgement for three seconds after acceptance (`use-composer-ack-expiry.ts`, `external-send-status.test.tsx`). Presence never classifies an agent.
- **A human Stop drains the stopped sender's existing queue.** Phone and tagged Stops share the existing recipient membership fence (`lockAgentCommandQueue`) and cancel pending orders from the same sender and source Room/corner up to the Stop transaction timestamp (`dropQueuedOrdersForStop`). Other senders, human mentions and later orders survive. The Stop line gives the queued count and one private report returns to the sender in the same transaction. An agent stops a turn it commands with the `stop` tool (`stopAgentTurn`, `commander.ts` `stopCommandedTurn`): its own order behind the turn, or a turn in a corner it opened. Others are refused and nothing stops. A follow-up order sent after the stop runs next (`AGENT-STOP-1`/`-2` in `commander-recovery.integration.test.ts`). Coverage: `agent-command.integration.test.ts`; set `BEELINE_STOP_TEST_POSTGRES_URL` to an isolated loopback PostgreSQL to exercise the concurrent claim and order-arrival proof.
- **Drafts.** Top-level Room `postAgentDraft` is a successful no-op (C109, `DaemonService.liveOutput`); corners store and publish drafts. Draft rows key on agent + request (`draft-settle.ts` `liveDraftRowId`), anchored at the turn's first snapshot. `LiveHub` reaches only listening sockets, so `PhoneService.liveDraftSnapshot` hands a late subscriber the current draft once. `turn-stream.ts` (`AgentTurnStream`) owns the bounded draft lane and one durable reply; corners also keep narration.
- **An ordinary final reply commits in one statement.** `DaemonService.postRoomMessage`'s no-mention path does authority, attachments, turn settlement, insert, command completion, draft cleanup in one CTE (`daemon-service.completion-latency.test.ts`). Agent-to-agent hops count from `triggerMessageId`; the third hop persists without a delivery mention.
- **Server commands are the only helper work authority.** `agent-command.ts` stores `input`/`resume`/`stop`; `server-command-intake.ts` claims them; agent tags in a committed reply dispatch in the same statement up to depth 3. `getDaemonBootstrap.pendingRooms` binds waiting surfaces before reconciliation cleanup (`room-runtime.ts`). `commandValidityCtes` fences superseded source facts and workflow attempts at delivery and claim. Pending commands retain their authority across disconnects. One invocation claims the place’s waiting inputs, reads its current state and includes private orders/reports once with their source files and request IDs; corner reports retain the opening commander’s return route. Missed notifications do not require individual results; invocation end consumes claimed wakes rather than returning them to pending. New arrivals wait for the next invocation; only an explicit Stop interrupts. Coverage: `agent-return-queue.postgres.test.ts`, `agent-turn-batch.test.ts`, `QUEUED-TAGS-REPEAT` in `agent-command.integration.test.ts`, `QUEUE-1` in `commander-recovery.integration.test.ts`. Conversation windows (`RoomConversationInput.window`, `warm-transcript.ts`) are context, never authority.
- **Connection-owned turns.** A claim belongs to its helper connection until the agent reports a result or the connection closes. Close hands unfinished commands back to pending; the next connection claims them with a new generation. No resend timer, lease sweep, startup backoff, silence notice, automatic review retry or workflow turn failover schedules another turn. An explicit failed result records one plain failure or reports privately to the commander. Coverage: `agent-turn-lifecycle.test.ts`; the connection-close hook belongs to `connection-presence.ts`.
- **A one-human, one-agent Room accepts untagged human messages; a newly provisioned starter pair defaults to Beebee.** `soloRoomAgentSql` (`agent-command.ts`) counts current active Room memberships inside the existing phone write/access and routing reads; no extra membership round trip. Only top-level non-DM Rooms qualify, and any typed mention suppresses the inferred target. Routing reuses the DM/tag target loop, access policy and deduplicated commands; corners, multi-human Rooms, other multi-agent Rooms, System messages and agent messages retain their routing. Coverage: `solo-agent-routing.test.ts` (phone send → command claim → reply → Room read) and `agent-command.scaling.test.ts`.
- **Mentions are read, never stored.** `message-mentions.ts` (`resolveCurrentMemberMentions`, SQL twin `taggedIdentityIdsSql`) matches exact current handles against current Room membership. `agent-access.ts` alone decides who may address an agent; `noteUnansweredMentions` writes one line per reason (not a member or policy refusal; offline requests remain pending without a notice). At most one push per recipient per agent turn (`background.ts`).
- **MCP webhook delivery follows committed events.** `runMcpWebhookDelivery` drains each queued delivery once under an atomic claim. Failed or abandoned deliveries create no retry deadline. Later messages are independent events; answering a tag cannot be followed by timed re-wakes (`owed-tag-replies.test.ts`). Shutdown drains the active request.
- **Tray expiry is evaluated on reads.** `needs-you.ts` reads current question/card validity from stored timestamps. No display-expiry sweep or timer invalidates the Tray, badge or owed rows.
- **Server work is event-only.** `background-work.ts` drains independent committed source events; startup and elapsed time cannot admit ordinary jobs. The [corner machine](agent-corners.md) separately replays recorded commanded work at startup and listener resync. `owner-schedule-clock.ts` is the sole server timer owner and fires only owner-created schedules (including authorized workflow schedules). There are no retention, media, lease, pending-attachment or idle sweeps, next-day nudges, failure retry clocks, or connection timer chains. Each job retains its own atomic database claim; there is no global leader, takeover clock or connection wait. The zero-exception architecture rule and planted rejection test protect this boundary (`scripts/server-timers.test.mjs`, `background-work.test.ts`, `agent-schedules.test.ts`).
- **Phone operation outcomes follow request events.** HTTP/socket dispatches record their final outcome once in `OperationOutcomes`; each instance flushes pending counts from recorded requests and drains active writes on shutdown. There is no flush or retention clock. Successful batches subtract only committed counts; new outcomes retain failed counts for their next event. The refusal diagnostic query is `OPERATION_REFUSALS_SQL` (`operation-outcomes.test.ts`).
- **Sidebar-only sockets receive previews by capability.** A `subscribe` with `sidebarPreviews:true` gets complete message deltas up to (2 KiB UTF-8) outside its `viewing` Rooms and bounded `sidebar-preview` events above that limit; older clients and viewed Rooms retain full message DTOs. `sidebar-preview.ts` owns projection and validation, including server-resolved mentions beyond the text cap. The list applies complete deltas to Room caches and invalidates cached Rooms on previews; covering reads provide complete large messages on open. Turn/corner state and Room-detail invalidations keep their existing paths; voice cards use a covering list read. Coverage: `server.test.ts` (`NET-HOL-1`), `sidebar-preview.test.ts`, and the mobile list/connection tests.

- **Live fanout crosses machines through PostgreSQL.** `postgres-live.ts` owns id-only triggers and a session `LISTEN` (`DATABASE_LISTENER_URL` when the main URL is pooled). Initial failure parks without a reconnect timer. Actual connection loss reconnects; a failed acquisition parks until an independent successful database recovery. Late retired-socket notifications and initialization completions cannot restore readiness (`postgres-live-recovery.test.ts`). The phone holds one `LiveConnection` and paints committed rows from their deltas, reading only what no delta describes.
- **Idle reads and report clearing stay corner-scoped.** `corner-idle.ts` materializes the requested live corner and evaluates its historical boundary once. `corner-owed.ts` and `corner-waiting-report.ts` use indexed first answers and forwarded-report origins; nested SQL builders must not shadow the caller’s corner alias. Message triggers hold journal locks, so report clearing excludes archived corners before deriving waits. Presence announcements commit before command repair/restart receipts acquire journal locks. The loopback PostgreSQL workload proof is `slow-query-workload.postgres.test.ts` (1,895 Rooms, 416,880 messages); `IDLE-SCOPE` in `corner-attention.integration.test.ts` guards episode isolation. Every completed production query over one second reports a fingerprint and literal-redacted SQL preview through `query-profile.ts`/`sentry.ts`, including profile-map overflow, without changing query execution.

- **Phone reconnection reads again.** Phone subscriptions use ordinary `LiveHub.subscribe`; there is no resume cursor or phone journal replay. A transport read failure settles once, and an idle broken connection asks the open screens to read again. Subscriptions read current full draft state from the server, with no timed transport cache or append reconstruction. The committed journal remains for the separate MCP member stream (`committed-journal-schema.ts`). Proof: `live-connection.test.ts`, `phone-socket.read.test.ts`.
- **Server ownership evidence follows authenticated traffic.** `ConnectionPresence` writes its aggregate lease on registration, requests and control events. Idle time never renews leases or scans stale servers; an actual connection close returns its commands to pending. Coverage: `connection-presence.test.ts`, `daemon-live.test.ts`.
- **One phone socket and recovery loop.** `LiveConnection` owns authorization, request/reply, Room subscriptions and the push event switch. A transport read failure settles on its first attempt; a server refusal settles once without closing the socket. Only an explicit socket request transport failure sets the one app-layout banner; the next answered request clears it. OS/browser network-online and foreground events ask the open screens to read, reconnecting through the same socket owner without retries, polling or backoff. Concurrent reads share a connecting replacement; writes retain their existing intent/outbox semantics. Foreground covering reads restore the socket and subscriptions. Existing request deadlines settle unanswered reads and writes; no heartbeat or HTTP deadline decides connectivity. Cached responses stay visible while reading. Missing updates and malformed previews re-read the affected Room. Coverage: `live-connection.test.ts`, `phone-socket.read.test.ts`, `phone-live-output.test.ts`, and `phone-socket.integration.test.ts`.

- **Retained sockets still cover skipped reads.** `useRoomSurfaceSession` records incomplete deliveries (including sidebar previews and invalidations) while hidden and makes one covering Room read on activation when visible. The visible Workspace/Room deck similarly calls its existing `refreshMissed()`/`ChatListStore.catchUp()` paths; returning without skipped work adds no read. A covering read consumes pending invalidations when it starts, so an older response cannot discard later work. Identity fences prevent old sessions from issuing activation reads. Coverage: `useRoomSurfaceSession.test.ts`, `channels.test.tsx`.
- **Phone clients use the live socket for writes.** `phone-operations.ts` handles authenticated requests from `phone-socket.ts`. HTTP retains pure reads and the closed `NON_PHONE_HTTP_WRITES` set used by deployment/free-agent proof tools and the corner fixture controller. Other HTTP operation, voice-control, read-mark and diagnostic writes are refused; current mobile actions use the socket. Binary media/audio and the vault's helper-bound secret ceremony retain separate HTTP boundaries. Existing optional command identities still use the same socket dispatcher. `LiveConnection.request` is the one mobile sender; messages retain the existing outbox and stable message IDs. The zero-allowance `phone.write-door` rule in `architecture/invariants.json` confines request serialization and domain execution, including within owner files. Coverage: `phone-socket.integration.test.ts` and `scripts/architecture-invariants.test.mjs`.
- **A read never announces itself.** The quiet operation set (`phone-operations.ts`, over `PHONE_READ_OPERATIONS`) publishes no Room invalidation: phones reread on one, so a read that announced it (`listRoomWorkflowRuns` in a corner) looped. REST read marks, diagnostics and services that already publish their own changes remain quiet too. Vault secret submission remains HTTP-only, using Fly replay to the helper’s server; it is absent from the operation map and refused over the socket.
- **Send acknowledgements follow commit, not analytics.** Phone HTTP/socket adapters opt into `PhoneService.observeSentMessage` scheduling onboarding observation through the physical database's tracked background work after the response can queue. Direct service calls retain completion of their onboarding milestones. Database shutdown drains tracked work; adapters without a background-work tracker await observation instead. Observation failure never rejects a committed message or reply. Coverage: `SEND-ACK-1`/`SEND-ACK-2` in `phone-socket.integration.test.ts` and the transport milestone regression in `free-agents.test.ts`.
- **Mobile storage and reads.** `surface-storage.ts` persists only response + outbox partitions; cold open installs invalidation, then one authenticated covering read. Read marks are server-owned (`room_read_marks`; `RoomView.viewer.readCursor`). The socket requests `roomStateProjections` and sends reader-scoped `read-state` and authorized `room-commands` projections (`PhoneService.liveReadState`/`liveRoomCommands`; `read-cursor.test.ts`), so sends and viewport marks do not refetch the Room or chat list; older phones retain their invalidations. Optimistic outbox rows are not committed read boundaries (`room-send-frame.ts`, `read-cursor-advance.test.ts`). `buildReplyCommand` (`reply-command.ts`) alone writes `h`/`e` tags.
- **The Needs-you tray is a server projection** (`apps/server/src/needs-you.ts`): a cell is a message that tags the viewer and asks (ends `?` or says please/approve/feedback), or a pending approval card the viewer can decide (`APPROVAL_QUERIES`: grant, write access, question choice, connector offer, sign-in, Trusty Squire), each filtered by its decide operation's own authority rule. Needs-decision reports and `ask_choice` accept an optional plain one-sentence `ask` (≤140 characters), with automatic extraction when omitted; reports store it in message card metadata and system approval writers generate it (`tray-approval-ask.ts`). The tray renders the server's plain ask; legacy rows choose a question or the first report sentence, strip markdown and shorten hashes, preserving the start. Coverage: `needs-you.test.ts`, `commander.integration.test.ts`, and Tray's `tray-ask-1` Chrome proof. Badge/bootstrap reads use `markSeen:false` and never start expiry. The visible Tray batches viewable unseen question ids into `markNeedsYouSeen`; its idempotent server acknowledgement starts the clock and returns expiries without another read. Legacy list reads still mark seen by default. Questions leave on tap/dismiss, a later viewer message, or 24 h after first paint; approvals leave on explicit tray dismissal, decision, expiry or close. Inline tray actions reuse `decideAgentGrant`, `decideWritePermission`, `answerChoice` and `skipChoice`; bound grant scripts stay available behind the shared disclosure; option consequences stay visible. Squire approvals open their own ceremony directly from the tray, while the source link opens their @System message. Dismissal never decides. Squire expiry is stored on its card; `backfillSquireApprovalExpiry` closes legacy stale cards.
- **Presence recovery bounds candidates before resolving tags** (`ConnectionPresence.observe`, `PushDeliveryLoop.runOnce`); inlining the tag matcher exhausted production pools in v0.0.95.
- **Room joins go through `membership-join.ts`.** Sign-in and `migrate()` create no membership; a person with no Workspace lands on create-or-join. `createWorkspace` makes a public `#general` (`first-room.ts`). An explicit join writes one `member-joined` note; a Workspace arrival retains its membership records without a System DM or broadcast push. Corner access derives from the parent Room with no copied membership writes. A Room membership change refreshes owed items once over indexed child-message candidates, including forwarded cards and reports (`corner-owed.ts`); never issue one refresh per corner. The last-answer probe requires the Room-and-author index; Rooms without children skip the bulk refresh while retaining report refreshes. Production-sized invite proof: `invite-join-deadline.test.ts` with an isolated loopback `BEELINE_INVITE_TEST_POSTGRES_URL`; socket-loss confirmation: `invite-socket.integration.test.ts`. Evidence and reproduction: [invite redemption deadlines](invite-join-reproduction.md).
- **First entry goes from sign-in to Workspace creation to #general.** Beebee’s first message teaches Room replies, corners and shared connectors without a repository card. Cards are offered on coding or GitHub-connection intent, never on Workspace creation or joining. Identity editing stays in Settings; the legacy welcome-card flag is unused by clients.
- **Repository workflows** in the phone UI are dispatched only by human Workspace managers (`listRoomWorkflows`/`dispatchRoomWorkflow`, exact-repo token, stored default branch). Production releases use the authenticated agent form of `dispatchRoomWorkflow`: active turn and human-root provenance are required, an audit receipt is committed in the place, and attribution is sent to GitHub. See [release pipeline](release-pipeline.md).
- **Reviewer sign-in.** `apps/server/src/review-access.ts` owns the store reviewer identity and `BEELINE_REVIEW_SECRET` (constant-time compare, rate limited, misses 404); entry is only the `/review/` link.
- **Machine disconnects stay silent.** `connection-presence.ts` records release/claim state in `agent_connections` and `live_outputs` without a System DM or push. Offline corner wakes remain queued silently (`machine-offline.test.ts`). A free starter agent is never offline: its released connection stays reachable and its wakes start its Fly Machine ([free agents](free-agents.md), `free-agents.test.ts`).

- **Agent members reads expose assignment facts only within the Room.** `listRoomMembers` extends owner/host metadata with selected model, reported billing, remaining provider windows (fractions plus reset times), key dollars or credits, free token allowance, and the parent Room reviewer role (`agent-member-metadata.ts`). Unknown billing or allowance stays absent; snapshot timestamps preserve age. The workspace roster keeps only public metadata. Coverage: `agent-member-metadata.test.ts`.

## Negotiated Room tool expansion

`PhoneService.readRoom` returns the existing complete Room answer. Explicit disclosure/More/Open actions in `ActivityTimeline.tsx` send ordinary `readRoomTools` requests on the same socket. These reads check current membership in the server handler and have no read certificate or final enqueue fence. `room-router-read.ts` retains only the SQL message-tag helper shared by plain reads.

- **No phone router activation.** The phone read router, build coordinator, read capture schemas, Tray clock readiness and schema negotiation marker are removed. Migration disables their old triggers on upgraded databases. `membership-authority-schema.ts` retains the shared membership writer lock needed by helper effects and the separate MCP credential stream. Existing helper/write rollout controls remain outside phone reads.

- **Transport enqueue locks current access rows.** `room-access-lock.ts` holds the Room, parent membership and Workspace membership through synchronous enqueue; MCP also holds its current token, connection, member and optional family. Provider responses are awaited after commit. The model, MCP stream and helper-overlay PostgreSQL suites cover revocation and archival contention.
