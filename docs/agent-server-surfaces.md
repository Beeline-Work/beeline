# Server-indexed surfaces and Room reads

- **Connected app activity requires pickup.** `show_dispatched_agent_work` creates `pending:` working placeholders only for Beeline-machine agents; Rooms MCP members become working through `claimAgentCommand`, shared with helper pickup. The one-time `connected-app-placeholders-v1` cleanup removes legacy app placeholders, preserving real turns. Corner reports to a connected app supersede unhandled reports with the same recipient, sender, origin and status, keeping the newest text and recording `superseded_report`; a live claimed report retains its authority. Machine queues and reports originating outside corners retain their existing behavior. Coverage: `connected-app-activity.integration.test.ts` (`R1`); built report → phone-read proof: `node --import tsx scripts/prove-connected-app-activity.mjs`.

- **Answered private blockers cannot wake their commander later.** The report's durable `waitingAnswered` marker also fences pending or expired report commands at delivery and claim, including released digest sources. A live claimed report continues; unrelated digest work survives. Coverage: `STALE-ANSWERED-REPORT` in `commander-wakes.integration.test.ts`; production trace and built HTTP proof: [answered report reproduction](answered-report-reproduction.md).
  A later private order from the report recipient to its author in the origin corner also answers a blocked/needs-decision report. This covers delegates who are not the primary implementer and therefore have no attention-index blocker (`STALE-DELEGATE-REPORT`).

- **Deliberate silence survives every harness.** `no_reply_needed` calls `markAgentTurnSilent` to persist `completion_kind='no-reply'` before acknowledging, without completing the command or revoking in-flight write authority; `postAgentTurnReceipt` preserves it. `DaemonService` acknowledges and discards later final text for that turn before public insertion or private report routing, including the atomic reply path. Whole final silence declarations are no longer filtered: final text publishes as written, and the only silence path is the `no_reply_needed` tool call. The generation and cancellation authority checks still apply. Coverage: `agent-command.integration.test.ts` and `commander.integration.test.ts` (`Reproduction R1`). Queued files drain through the ordinary reply writer before explicit silence is recorded; files attach to an existing same-turn post or form a file-only message. A report wake whose automatic inherited report is skipped falls through to public reply delivery instead of discarding prose and files. Closing prose after an explicit post to the same place and turn generation is retained as a Turn summary activity note, rather than a second conversation message; posts elsewhere do not suppress it.

- **Voice uses existing agent identities and ordinary orders.** `apps/server/src/voice-service.ts` owns membership and dispatch; `voice-room-runtime.ts` speaks command-provenance reports without capping real work. Short-press dictation remains separate. Providers, native runtime requirements and isolated proof commands: [voice mode](voice-mode.md).

- **Computer activity is an observation, never an owed reply.** `computer-session.ts` retains Squire's preview channel, HTML and latest frame while any viewer remains; `ComputerSessionCard` preserves that preview's token when opening the full view. `agent-command.ts` coalesces one pending observation per share behind other work and refreshes its source at claim; Room/corner turn loops accept silence, and `turn-silence-notice.ts` never retries or inscribes an activity failure. Coverage: `computer-session.test.ts`, `server-command-intake.test.ts`, and the Room/corner turn tests.
- **Shared browser links enter through Beeline.** Point people at the live browser card. `browser_share start` returns its message id as `cardId`, its source session id for ending the share, and a plain instruction to open the card posted in this place. It returns no URL; the raw `/s/<id>/` address offers web and app entry without disclosing session metadata. The app obtains a viewer token with `openComputerSession` after sign-in. Tokens and current Room/agent authority still gate the viewer.
- **Computer share upstreams are allowlisted.** The server fetches and tunnels to a share's upstream URL, so `createComputerSession` accepts only `body:` or an `https:` URL whose host is under `*.trycloudflare.com`, the host Squire `operate_share` returns. IP literals, `localhost` and `.localhost`/`.internal`/`.local` hosts fail. Coverage: `computer-session.test.ts`.

- **Plain reads retain complete results.** Needs You reads/counts include every qualifying question, including beyond 500. Scheduled Work reads and public webhook metadata follow active Room membership (`subscription-webhooks.ts`); mutations and secret token controls retain management authority. Net result codecs validate structure without whole-result byte/node quotas; input limits remain. Proofs: `read-surface-growth.postgres.test.ts` and `packages/net/src/read-surface-growth.test.ts`.

- **Server-indexed surfaces own durable answers.** `phone-service.ts` owns paint-ready queries; `packages/api-contract/src/phone.ts` owns DTOs. Screens send ordinary operations through `live-connection.ts` and render validated responses. `server-read-owner.ts` retains the existing list/Tray caches and plain live-delta updates; `surface-boundary.test.ts` protects their cache writes. No read capability or family negotiation is required.
- **A Room GET does not carry child corners.** `PhoneService.readRoom`/`RoomView` stop at the Room; corners come from `RoomViewClient.corners`, and the chat list's `cornerCount`/`openCorners` feeds `DesktopRoomCorners`. Opening a Room makes one live subscription (`useRoomSurfaceSession`); never expand watch-filter keys into per-corner subscribes.
- **A Room payload is projected, never all-or-nothing.** `readRoomView` (`phone-guards.ts`) fails only on a missing `room.id` or `messages`; unreadable optional fields are absent, never invented; unknown `role` reads `member`; `repositoryResolution` reads `unverified`.
- **Completed commands cannot leave working turns behind.** Completion receipts may close a still-working turn even when its command already completed; replay preserves existing terminal outcomes. Superseded reviews close their turn in the command transaction. The one-time `completed-command-turns-v1` migration fails existing working turns whose command is complete and which have no live claimed lease. Proof: `stuck-turn-1` in `agent-command.integration.test.ts` and `migrations/completed-command-turns.test.ts`.
- **Composer status is server-owned.** `RoomView.pendingAgentCommands` and the send ack show `Waiting for @agent` from an accepted human command until claim; `RoomView.latestAgentTurns` shows working from committed command dispatch, before helper acknowledgement. Lifecycle status and restart wording require a claimed, unexpired command matching the real turn generation (`agent-lifecycle-command.test.ts`). Real working turns remain visible until terminal state or 90 s without a receipt. `renudgeStrandedPendingCommands` requires one helper ID and re-pushes eligible pending commands only on connection/reconnect or the existing pickup transition; no minute sweep or30/90-second retry admission remains. Bootstrap enumerates pending member Rooms independently of the bounded hint batch; stored commander/startup deadlines remain owned by `CommanderWakeDeadlines`. - **A human Stop drains the stopped sender's existing queue.** Phone and tagged Stops share the Room/agent claim lock (`lockAgentCommandQueue`) and cancel pending orders from the same sender and source Room/corner up to the Stop transaction timestamp (`dropQueuedOrdersForStop`). Other senders, human mentions and later orders survive. The Stop line gives the queued count and one private report returns to the sender in the same transaction. An agent stops a turn it commands with the `stop` tool (`stopAgentTurn`, `commander.ts` `stopCommandedTurn`): its own order behind the turn, or a turn in a corner it opened. Others are refused and nothing stops. A follow-up order sent after the stop runs next (`AGENT-STOP-1`/`-2` in `commander-recovery.integration.test.ts`). Coverage: `agent-command.integration.test.ts`; set `BEELINE_STOP_TEST_POSTGRES_URL` to an isolated loopback PostgreSQL to exercise the concurrent claim and order-arrival proof.
- **Drafts.** Top-level Room `postAgentDraft` is a successful no-op (C109, `DaemonService.liveOutput`); corners store and publish drafts. Draft rows key on agent + request (`draft-settle.ts` `liveDraftRowId`), anchored at the turn's first snapshot. `LiveHub` reaches only listening sockets, so `PhoneService.liveDraftSnapshot` hands a late subscriber the current draft once. `turn-stream.ts` (`AgentTurnStream`) owns the bounded draft lane and one durable reply; corners also keep narration.
- **An ordinary final reply commits in one statement.** `DaemonService.postRoomMessage`'s no-mention path does authority, attachments, turn settlement, insert, command completion, draft cleanup and offline-notice withdrawal in one CTE (`daemon-service.completion-latency.test.ts`). Agent-to-agent hops count from `triggerMessageId`; the third hop persists without a delivery mention.
- **Server commands are the only helper work authority.** `agent-command.ts` stores `input`/`resume`/`stop`; `server-command-intake.ts` claims them; agent tags in a committed reply dispatch in the same statement up to depth 3. `getDaemonBootstrap.pendingRooms` binds waiting surfaces before reconciliation cleanup (`room-runtime.ts`). `commandRecoveryCtes` keeps the newest pending wake per Room on return, quotes superseded text as history, and fences stale workflow attempts at delivery and claim; fresh online traffic keeps its queue. At claim, pending human inputs from the same sender and place fold into the oldest request; later source ids, text and files enter its prompt in arrival order, and folded commands settle atomically. Any folded human request id remains a Stop handle for the combined turn. Deleted or stopped sources stay excluded (`QUEUED-TAGS-REPEAT` in `agent-command.integration.test.ts`; production metadata replay: `node --import tsx scripts/prove-queued-human-tags.mjs` after building the server). New orders, brief revisions and addressed human messages delivered during a running turn never stop it: `commander-wakes.ts` (`queueSteersBehindTurn`) joins them into one inbox digest in arrival order, which the next turn reads after the running turn ends. Only an explicit Stop interrupts (`QUEUE-1` in `commander-recovery.integration.test.ts`). Isolated startup replay: `npm run measure:fast-resume -w @beeline/body`. Conversation windows (`RoomConversationInput.window`, `warm-transcript.ts`) are context, never authority.
- **Silence and failure.** `noteFirstSilence` (`turn-silence-notice.ts`) owns silence/failure episodes, phrased by `packages/api-contract/src/turn-silence.ts`. Hiccups reopen the command (≤3 attempts, one give-up line); model-capacity/overload failures also retry agent-triggered commands through durable wake deadlines (30 then 60 seconds), retaining the assignment and reporting exhaustion to its commander (`CAPACITY-1` / `CAPACITY-COMMANDER-1`; built HTTP proof: `scripts/prove-review-capacity.mjs`); standing conditions complete it; transient corner-start failures stay pending. Corner unreachable reports also honor real turn and activity evidence since the wake, excluding optimistic `pending:` turns (`commander.integration.test.ts`, `turn-silence-notice.test.ts`).
- **Repeated silent automatic continuations stop.** `silent-wake-limit.ts` bounds automatic reports and background-tool continuations to three unanswered turns per agent, place and original human message, after the latest actual reply. Dispatch and terminal receipts stop further automatic continuations and leave one `could not answer` line in the person's original conversation. Coverage: `wake-storm-83` and `SILENT-END-1` in `agent-command.integration.test.ts`; production metadata fixture: `fixtures/wake-storm-83.json`; built HTTP proof: `node --import tsx scripts/prove-silent-wake-limit.mjs` after building the server. Corner restore reads are unchanged.

- **Phone operation outcomes are bounded telemetry.** `phone-operations.ts` counts both HTTP and socket dispatches once, with success status 200 and the existing refusal status/code or error class; no request-path database work or change to refusals/Sentry. `operation-outcomes.ts` registers new recurring work: every instance (including nonleaders) flushes on startup and every five minutes through `BackgroundWork`/`BackgroundJobRunner` and the jobs pool. ## Negotiated Room tool expansion

`PhoneService.readRoom` returns the existing complete Room answer. Explicit disclosure/More/Open actions in `ActivityTimeline.tsx` send ordinary `readRoomTools` requests on the same socket. These reads check current membership in the server handler and have no read certificate or final enqueue fence. `room-router-read.ts` retains only the SQL message-tag helper shared by plain reads.

- **No phone router activation.** The phone read router, build coordinator, read capture schemas, Tray clock readiness and schema negotiation marker are removed. Migration disables their old triggers on upgraded databases. `membership-authority-schema.ts` retains the shared membership writer lock needed by helper effects and the separate MCP credential stream. Existing helper/write rollout controls remain outside phone reads.
