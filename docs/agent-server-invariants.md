# Server safety and feature invariants

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

## Database and reads

- Keep bounded app/enrichment/health pools separate from long migrations (`apps/server/src/database.ts`). Project core Room data before optional enrichment; boot asserts only the migration-final `beeline_schema_state`. Release isolation: [release pipeline](release-pipeline.md).
- **`deleteWorkspace` is owner-only and a real `DELETE`** relying on FK cascades. It checks existence before ownership (idempotent retries), writes `workspace_deletions` + per-member notices, revokes tokens only for agents with no other membership, and leaves media to `media-ttl.ts`. Every FK column into `messages`/`rooms`/`workspaces` must carry a leading-column index — an unindexed one forces Postgres to sequentially scan that whole child table per deleted row during the cascade, which is slow enough on a real table to blow the app pool's `APP_STATEMENT_TIMEOUT_MS` and leave the client's delete request hanging with no answer. Guarded by the `cascade-path foreign keys stay indexed` test in `database.test.ts`; `messages` itself is busy enough that a new index there goes through `createIndexConcurrently` in `migrate()`, not inline schema SQL.

- **Push delivery drains a write-time device outbox.** `push-outbox.ts` installs transactional message/device and workspace-join fanout; grouping context records message IDs on writes. `PushDeliveryLoop` leases due rows with `SKIP LOCKED` and reads message content by primary key, including turn and burst siblings. Existing claims retain delivery/retry/read-clear authority during rolling cutover; the migration-only `push-outbox-v1` backfill catches up the previous hour idempotently. The jobs pool limits statements to 2 seconds and lock waits to 500 ms; maintenance deletes run in batches of 1,000. Proof: `push-outbox.test.ts` (`R-PUSH-SCAN-LOCK`, isolated loopback PostgreSQL via `BEELINE_PUSH_TEST_POSTGRES_URL`), with existing push behavior suites. Backlog diagnosis, expiry rules, alert signal and production follow-through: [push backlog recovery](push-backlog-recovery.md).

## Grants and retirement

- **Agent Grants have one vocabulary and one authority axis.** `packages/api-contract/src/agent-grants.ts` owns kinds, statuses, the command-rule parser (`parseCommandGrantTarget`; `commandGrantMatches` is an argv prefix; approved command grants follow the agent within their Workspace across Room/requester changes) and the decision line; policy follows `docs/approval-matrix.md`; `surface-capabilities.ts` lets a corner dominate a Room. Yolo defaults on (`backfillYoloModeDefault`) and is forced off in public Workspaces; credential-file argv and unread scripts (>4096 B/120 lines) still stop. Human profiles show the grant ledger (`readWorkspaceMembers`, `MemberGrantRow.tsx`, wording in `grantProvenanceLine`); an active `shared_asset` row alone offers revocation there. The agent settings page shows none.
- **Removing an agent retires it; its work survives.** `PhoneService.removeAgent` → `retireAgentFromWorkspace` (`agent-retirement.ts`) ends memberships, revokes all its daemon tokens and unused exchanges (`apps/server/src/daemon-credential-lifetime.ts`, shared with rollback and Workspace deletion) and grants, hides the identity, clears configuration, and deletes schedules; corners, turns and messages stay. A helper retires only on 403 `agent_removed` (`isAgentRemovedError`), never on transport errors, 5xx, or plain 401.
- **Issued capabilities follow membership lifetime.** Pairing claims lock the issuer's current Workspace membership; leave/removal deletes their unclaimed codes. A legacy permission requester's decision locks current Room and Workspace memberships; the manager path keeps its policy (`apps/server/src/phone-service.ts`). Credential and pairing races: `apps/server/src/authorization-lifetime.test.ts` (isolated PostgreSQL via `BEELINE_LIFETIME_TEST_POSTGRES_URL`).

## Room departure

- **Leaving a Room.** Any human can leave a top-level Room (`PhoneService.leaveRoom`, under the Room row lock); the last Workspace owner/admin in it deletes it for everyone and must pass `confirmDelete: true`. `leaveDeletesRoom` drives `buzz/room-leave.ts`. Swiping a DM writes a per-viewer `chat_dismissals` row hidden only until newer inbound activity.

## Feature contracts

- **Public agent `post` text excludes leading inline reasoning blocks.** `agent-post-text.ts` removes initial `<think>`/`<thinking>` blocks; `DaemonService.postCornerMessage` refuses reasoning-only input before storage. Ordinary replies and quoted tags later in a reply stay intact. This does not classify untagged model-authored prose or establish the cause of an inaccessible incident. Coverage: `agent-post-text.test.ts`, ACP/proxy `R-REASONING-POST` cases and the built MCP → phone-read proof in `scripts/prove-public-post.ts`.

- **Incoming subscription webhooks** use the existing subscription wake path with fixed saved actions and quoted outside payloads. Workspace admins manage Room links; human DM members manage links in their own DM; tokens are encrypted and only phone reveal/rotate returns them. Ingress and rotation serialize on the subscription. Sender contract and retention: [subscription webhooks](subscription-webhooks.md); proof: `subscription-webhooks.test.ts` and `apps/mobile/evidence/subscription-webhooks/README.md`.

- Sentry capture, authenticated Telegram forwarder, configuration and post-release proof: [error monitoring](error-monitoring.md). Keep Telegram outbound-only and exclude forwarder failures from recursive capture. Caller validation failures use `ExpectedRefusalError` (or `CommandRefusalError` with an HTTP status); `captureServerError` excludes that shared type, never matching refusal message text. Unexpected exceptions and provider outages remain reportable. Handler proof: `BEELINE-SENTRY-REFUSALS` in `sentry.test.ts`.

- Private operator dashboard cohorts, fixture exclusions and metric provenance: [dashboard API](operator-dashboard-api.md); aggregate queries and regressions live in `operator-dashboard.ts` and `operator-dashboard.test.ts`.

- Wallet settlement and push authority: [wallet tools](wallet-tools.md), `wallet-notices.ts`, `wallet-webhooks.ts`. Indexed incoming receipts stay in `wallet_transactions` without a System DM. Outgoing transactions, failures, refusals, pending notices and webhook receipts without a history row retain their notices.
- Agent feedback stores up to 200 distinct items per agent per UTC day (`FEEDBACK_AGENT_DAILY_CAP`), then retains excess reports in one daily overflow item with a count and latest summary/context. Existing duplicate handling remains in `feedback.ts`.
- Operator System DMs require lunchboxfortwo's human-rooted command, configured System-sender authority, and their own agent. Durable batches, audit and tool counts: [operator System DMs](operator-system-dms.md), `operator-system-dm.ts` and `operator-system-dm.test.ts`.
- Feedback resolves silently through `notify_feedback_fixed` with a merged PR in `BEELINE_FEEDBACK_REPOSITORY`; `notify: true` sends Fixed notices only for an explicitly ordered notice in a configured System sender’s human-rooted turn; storage and policy: `apps/server/src/feedback.ts`, [triage workflow](workflows/feedback-triage.json).
- The GitHub star card acts only on the person's own tap and never gates anything (`github-star-prompt.ts`, `StarPromptCard.tsx`).
- Corner Apps are installed data, never downloaded code; permission manifest: `packages/api-contract/src/corner-apps.ts`.
- Agent faces and names are assigned together by the server under the Workspace lock (`assignSeededAgentIdentity`, `PhoneService.claimAgentConnectPairing`); never re-derive a face on the client. Keep face IDs aligned in `packages/api-contract/src/faces.ts` and `apps/mobile/sources/buzz/faces/index.ts`. Human handles win collisions (`workspace-handles.ts`).
- **A non-agent system author is a hidden `kind='human'` identity** with a fixed id (`SYSTEM_IDENTITY_ID`, `REVIEW_IDENTITY_ID`, `SCHEDULE_SCHEDULER_ID`), never a new `identities.kind`. `system-line.ts` sends essential approvals, sign-in, security and money notices to the recipient's read-only `@system` DM; routine Workspace facts stay in their committed state (`assertRoomIsWritable`); `migrations/one-system-thread.ts` retires every other bot DM and its contents. Tray decisions reuse the transcript's grant/permission/choice operations; Squire retains its own ceremony (`needs-you.ts`, `tray.tsx`).

## External apps and MCP

- **Connected app tools execute only at the server boundary.** `apps/server/src/app-connections.ts` resolves the connection; Body's `list_app_tools`/`execute_app_tool` call `DaemonService` with turn authority and never hold provider tokens.
- **Squire API reconnect requests owner setup on the existing route.** An existing vault key alone cannot answer an explicit repair request with ready; `connect` retains owner consent and returns a repair goal without the old reference. Recheck normally after repairing the credential, then verify the requested provider resource. Coverage: `SENTRY-ACCESS` in `app-connections.integration.test.ts`.
- **Registry discovery and installation use the connection policy** (`mcp-registry.ts`; OAuth in `apps/body/src/registry-mcp.ts`). Connector search queries the Registry for every term and probes only known company domains (`company-mcp-discovery.ts`, public DNS pinned to HTTPS sockets, bounded cache/timeouts). A person's explicit verified MCP selection may replace a Squire API app route while preserving vault keys; automatic/agent routing and Composio routes retain their policy. Registry grouping uses publisher namespaces, never claimed websites. Proof and limits: [MCP discovery](../apps/mobile/evidence/mcp-discovery/README.md), `company-mcp-discovery.test.ts`, `app-connections.integration.test.ts` (`MCP-DISCOVERY-1`).
- **Connection receipts DM only what needs a human** (`ConnectionUsageRecord.eventClass`). Agents use `find_connectors` to settle a service and `connect` for server-owned setup in any surface. Legacy `offer_connector` and `connect_app` aliases stay hidden for one release. `pairConnector` re-arms a conflicting row. A Squire `google_session` wall becomes an in-Room reconnect card (`npm run prove:squire-login-wall`).
- `external-mcp-capabilities.ts` stores only the profiles `squire-credential-use`/`squire-app-access`; Squire spend verbs need an owner-signed one-use envelope.

## Object storage

- Pending agent attachment queues are cleared transactionally by corner archival. `pending-attachment-cleanup.ts` reconciles at startup and hourly through the jobs pool, deleting at most 1,000 rows per pass: archived corners immediately, otherwise rows older than 24 hours with neither an active request command nor a working turn. Media bytes keep the existing TTL; tombstones survive. Coverage: `CLEANUP-ATTACH-1` in `corner-lifecycle.test.ts` and `data-cleanup.test.ts`. After deployment, verify `SELECT count(*) FROM agent_pending_attachments a JOIN rooms r ON r.id=a.room_id WHERE r.parent_id IS NOT NULL AND r.archived_at IS NOT NULL` returns zero after reconciliation; never manually delete production rows.

- `apps/server/src/object-storage.ts` is the one SigV4 client (Fly Tigris); `object-service.ts` owns rows. Byte lifetimes live in `media-ttl.ts`: person uploads `MEDIA_TTL_HOURS` (24), agent artifacts `ARTIFACT_TTL_HOURS` (7 days). An expired object answers 410 `media_expired` from the `object_expirations` tombstone, and the UI says "expired", never "failed". `post_artifact` validates per MIME in `artifact-validation.ts` (≤ `ARTIFACT_MAXIMUM_BYTES`).
