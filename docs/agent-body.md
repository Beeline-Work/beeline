# Body agent invariants

- **The helper is a monolith-only thin Room client:** `ThinDaemonCore` → `RoomRuntimeCoordinator` → `MonolithRoomTurnLoop`, every operation through `DaemonApiClient`. Room and corner loops share `agent-home.ts`, `acp.ts`, `session-scheduler.ts`, model selection, persona delivery, bwrap spawning, and the agent MCP (`read-only-mcp.ts`).
- **One helper process per machine, one heartbeat-checked socket.** `beeline daemon --machine` (`machine-helper.ts`) hosts every agent in-process (`agent-runtime.ts`); an agent crash retries only that agent indefinitely (5 s doubling to 60 s); auth/configuration and other permanent 4xx startup refusals retain the error until a real revision or explicit start. The machine has only starting/serving/stopping states; its native supervisor restarts every exit unless explicitly stopped. The existing local watchdog tick asks every `ThinDaemonCore` to acknowledge work-loop progress before sending `WATCHDOG=1`; status and socket traffic never feed it (`workloop-watchdog.test.ts`, opt-in `workloop-watchdog.systemd.test.ts`). Non-retryable registration and socket-upgrade refusals park for the channel/link lifetime; archived-cleanup refusals persist across helper starts, preserve local code and branches, and reclaim only ignored generated output (`machine-link.refusal.test.ts`, `live-link.test.ts`, `corner-branch-sync.test.ts`). Established agents stay serving regardless of health prose; discovered surfaces without an observed fault do not imply degradation (`machine-helper.test.ts`, `surface-health.test.ts`). Heartbeats stop on permanent 4xx refusals (`turn-receipt-heartbeat.test.ts`). Helpers learn of work only through the socket (`no-polling.test.ts`): server pings every 30 s, the helper drops a socket silent for 75 s.
- **Background tool completion is push-driven.** `AcpClient.sessionPrompt` retains unfinished tool IDs after `end_turn`; corner clients also negotiate Claude ACP's `asyncTasks` extension because a detached Bash tool call completes before its job. Terminal tool/task notifications call `postBackgroundToolCompletion` with the originating turn generation. The server creates one deduplicated continuation command retaining its order chain, and refuses cancelled or stale generations. `SessionLifecycle.hasBackgroundWork` protects the harness from idle/capacity eviction until completion. Coverage: `acp-background-tools.test.ts`, `session-scheduler.test.ts`, `commander.integration.test.ts`.
- **Tool refusals are MCP `isError` results** logged via `tool-call-failure.ts`. Corner names (≤3 words) and objectives (≤24 words) are owned by `packages/api-contract/src/corner-text.ts`. Merge approval is head-bound (`corner_merge_approvals`: PR number + head SHA), never brief-revision-bound.
- **Top-level Rooms: read-only filesystem, unrestricted tools.** bwrap enforces the filesystem rule, not harness mode; `roomPermissionDecision` approves mounted MCP calls, plus shell and native read/search kinds when sandboxed (`harness-capabilities.ts`); native writes/edits remain refused. `ensureBwrapSandbox` remembers a failed install for 24 h. Permission decisions read tool identity, never wrapper shape (`read-only-policy.ts`). Without the sandbox, only native attachment reads are approved: every declared path must to stay inside this session’s `BEELINE_ATTACH_SCRATCH_ROOT/attachments` before and after realpath resolution; missing paths and escapes remain rejected (`attachment-permission.test.ts`).
- **Workspace assets, Room harness state.** `workspace-assets.ts` selects one machine + Workspace cache/AVD-metadata tree for every harness; ACP adapters use the operator-installed harness programs. No Workspace adapter or harness copies are installed; Room and corner launches keep the host adapter and share only caches. The Android SDK stays at its operator installation. `agent-home.ts` keeps each agent/Room's `HOME`, sign-in, config, sessions and plugin data at the existing path. Pending approvals remain server scoped by agent and Room. Codex's downloaded `cache` and `plugins/cache`, and Cargo `registry` are exact shared binds; Beeline adds no shared pip or Gradle override. Inherited toolchain settings pass through unchanged. `bwrap-sandbox.ts` masks the stable Workspaces and agents parents, then restores this Workspace's assets, this Room's home/cwd and only its required control file. The old `siblingAgentMaskPaths` remains for legacy private-layout turns. `credentialMaskPaths` still hides known operator credentials. Agents share one Unix account, so bwrap shapes ordinary path visibility and is not a security perimeter. A Room has private `/tmp`; keep rig runtimes under `$HOME`. `shared-asset-capacity.ts` applies a best-effort free-space floor and monitored private recovery reserve; private writes can race the monitor. Operator-only old-cache cleanup is in `startup-cleanup.ts`; its explicit apply command requires the helper to be stopped.
- **An agent can ask to isolate one shared cache category.** `request_shared_asset_isolation` in `read-only-mcp.ts` creates a pending `shared_asset` Agent Grant with a reason and Room card. Only a Workspace owner/admin or the agent's owner may approve or deny it; approval is standing, and the human grant ledger can revoke it. `workspace-assets.ts` selects the agent-private cache tree and `bwrap-sandbox.ts` applies exact binds from the next session; `session-config-fingerprint.ts` replaces a retained session after a decision or revocation. Categories are pinned in `agent-grants.ts`, never file paths.
- **Repository Rooms and corners get an exact-repository GitHub App token** (`getRoomGitHubToken`). Room sessions inject `GH_TOKEN`/`GITHUB_TOKEN` and respawn on token rotation; their filesystem stays read-only. The Room `gh` launcher gives an owner-selected personal GitHub connection precedence: Squire uses sealed HTTP; managed OAuth and registry MCP translate issue-comment creation to the connected provider tool. Automatic vault discovery alone does not select a personal account. Selection uses the latest connection route provenance, including verified owner completion of managed OAuth and authenticated owner opening of registry sign-in; disconnect/rediscovery does not restore historical selection. Existing tool authorization applies, and personal-provider refusals do not fall back to App credentials. `room-runtime.ts` installs a worktree-only credential helper for corners. Coverage: `room-github-auth.test.ts`, `monolith-room-turn.retention.test.ts`, `room-session.test.ts`, `app-connections.integration.test.ts`.
- **Corner working copies are disposable only after their work is durable.** `removeCornerWorktreeAndBranches` refuses tracked/untracked changes or a HEAD no `origin/*` ref contains. Corners share npm/pnpm caches and `CARGO_TARGET_DIR`; `warm-node-modules.ts` hardlinks a lockfile-keyed `node_modules`. Permanent archive refusals are recorded before optional preservation; `corner-disk-recovery.ts` serializes recovery across hosted agents, and `room-runtime.ts` yields reconciliation progress to the watchdog (`workloop-watchdog.test.ts`).
- **Imported MCP servers are `local` or `host`** (`mcp-route-class.ts`). A host server (Squire, or `beeline_route = "host"`) mounts only through an owner-approved `kind=mcp` route grant (`host-mcp-route.ts`). Squire uses one `SquireTaskRelay` connection per task (15-min idle lease) through the host broker.
- **Squire approval deadlines are lease bounds, not human decisions.** The forwarder clears a vault wait when `credential_fetched` returns without a URL, keeps retries correlated to the original requester, and fences pending responses racing an authoritative decision. Only Squire decision notifications wake the requester; elapsed local timers release tracking without inventing “no answer.” Vault calls have a 30-second transport deadline; browser calls retain their 210-second ceiling. Coverage: `squire-task-relay.test.ts`, `squire-mcp-client.test.ts`, `resource-mcp-facade.test.ts`; incident and matching proof: [late credential approval](late-credential-approval-proof.md).
- **Live Squire shares span model turns.** `squire-share-renewals.ts` renews `operate_share` on the session's owning connection and updates only matching live rows through `refreshComputerSession`; it does not extend the forwarder's idle lease. `computer-session.ts` treats an old upstream deadline as a liveness check, and consumes main-frame `navigation` notifications while the human controls the browser. Requires Squire 1.1.33. Coverage: `squire-share-renewals.test.ts`, `squire-task-relay.test.ts`, `computer-session.test.ts`.
- **Attachments reach the harness as content, never a URL** (`attachment-delivery.ts`): images go inline only when the harness (`promptCapabilities.image`) and the model (`openrouter-routing.ts` pins `input_modalities`) accept them. Only the message being answered is pre-downloaded; other transcript messages show `📎 name (type, size) id=<media id>` markers (`attachmentMarkerLines`) and `download_attachment` (`read-only-mcp.ts`) fetches one on request under `getRoomMessage` authority, sha256-deduped, with typed `not_found`/`forbidden`/`too_large`/`download_failed` refusals.
- **`post_artifact` path roots** are the checkout plus the agent's whole writable session home (`BEELINE_ATTACH_SCRATCH_ROOT`), checked by `resolveAttachPath`; `scratch_io(action:write)` writes only there. `helper-storage.ts` replaces the private scratch TTL sweeps: confirmed archive immediately removes whole private Room folders (local conversations included; server messages retain the transcript). Open surfaces preserve credentials, settings, browser profiles and harness conversation/resume state. Disposable private files and npm/turbo cache files expire independently after seven days; recent siblings and directory timestamps cannot pin old bytes. Model/tool generations and code copies retain whole-object publication/use checks. Scheduler leases fence Room and machine cleanup; processes, open files, mounts and emulator leases defer it. `storage-owners.ts` removes ended agents and the last local Workspace's assets, persists deferred cleanup authority, and identifies legacy checkout owners by the Room/remote/branch hash. Archived checkout facts persist independently of revoked Room access. A confirmed landed PR head permits local cleanup after squash merge; genuinely dirty/unpublished work remains protected. Shared checkouts retain publication guards. Trusty Squire stores are hard-excluded everywhere; tracked `skills/trusty-squire` is source code. `storage-filesystem.ts` repairs owned read-only download directories only during removal. Linux inventory streams `/usr/bin/python3` output with `O_NOATIME`; macOS uses native filesystem inventory, `lsof` and `mount`. Neither follows symlinks; unavailable process/filesystem evidence fails closed. `beeline storage --dry-run` / `--orphans` and `npm run dry-run:helper-storage` make only authenticated reads and inventory, without helper lifecycle actions or credential write-back. Unlisted private Rooms use seven-day disposable-file expiry without synthesizing an archive; failed lifecycle reads retain storage. Unknown lifecycle is reported separately from confirmed orphans. Coverage: `storage-bloat.regression.test.ts`, `helper-storage.darwin.test.ts`, `helper-storage.test.ts`, `storage-lifecycle.integration.test.ts`, `room-runtime.archive-cleanup.test.ts`. Machine evidence and causes: [storage bloat investigation](beeline-storage-bloat-root-cause.md).
- **Harness quirks.** pi ignores `session/new` `mcpServers`, so `pi-mcp-bridge.ts` writes an extension before spawn. `piHasNativeMcp` must probe with the session's own `agentEnv` (`PATH` above all), never this daemon's `process.env` — pi-acp resolves its own `pi` child against the former, and the two can name different installed Pi versions. pi-acp also forwards a Pi extension's `ui.notify()` (e.g. the bundled `mcp` extension's "servers need attention" warning) as an `agent_message_chunk` tagged `_meta.piAcp.notify`; `acp.ts`'s `agentMessageChunkText` must keep treating that as non-text so a harness infrastructure notice can never stand in as the agent's reply. Cursor speaks ACP through `cursor-acp-bridge.ts` (never `cursor-agent-acp`); its login is `~/.config/cursor/auth.json`, linked by `agent-home.ts`; the helper unit PATH includes `%h/.local/bin`. claude-agent-acp `settings` must be an object (`harness-tool-scope.ts`). `meaningfulHarnessStderr` filters pi's harmless `-32601` dump.
- **Pi instructions are delivered once per warm conversation.** `acp.ts` / `pi-session-instructions.ts` keep the initial Beeline rules in Pi's conversation, strip only an exact repeated leading block, and restore it for new/repaired sessions, changed rules, or a new journal compaction marker. Missing/unreadable journals resend conservatively. This applies to Rooms and corners; task text and attachment blocks remain intact. Regressions: `pi-session-instructions.test.ts`; ACP transport/token proof: `scripts/prove-free-agent-instructions.ts`.
- **Managed Pi startup skips informational subprocesses.** `pi-startup.ts` installs a process-local Node load hook for pi-acp, removing its synchronous version/update checks. Package/bin metadata must match the actual executable (including `PI_ACP_PI_COMMAND`); unrecognized executables get a bounded background version probe. Restore the original `NODE_OPTIONS` before Pi or tool children start. The rewrite is atomic: changed anchors or missing adapter bindings load the original source unchanged, preserving startup at the cost of synchronous informational checks. Coverage: `pi-startup.test.ts`; [Fly timing and cleanup proof](pi-startup-cut-proof.md).
- **Android emulator leases are per instance.** In the shared layout, `workspace-assets.ts` publishes read-only AVD metadata and agents use the operator's installed SDK; `android-emulator-lease.ts` gives each `beeline emulator -avd <name>` invocation unique writable userdata and a leased console/adb port pair in the installed emulator's 5554–5584 range. The legacy private layout still uses `android-agent-env.ts`. Agents share the uid and network, so explicit adb connections can still reach another emulator.
- **Assigned orders stay open until the worker reports.** The server does not audit each turn: a complete receipt and an expired execution lease consume the command without any report. Supervision of stalled corner work comes from corner state transitions (idle alert, waiting-on-human states); Room-addressed orders get no fallback alert. The helper's explicit `unreported_order:` failures (repeated-call guard, free-agent time limit, login required) still use the failed receipt → `noteFirstSilence` → `reportToCommander` route, unless the generation already reported or recorded a durable child/approval continuation. Reports follow recorded opening ancestry to the nearest live return place while retaining commander membership checks. Informational wakes can still end quietly; cancellation and stale generations retain their fences. Coverage: `commander.integration.test.ts`, `turn-silence-notice.test.ts`, `monolith-room-turn.failure.test.ts`, `acp-liveness.test.ts`. Squire decision publication failures during an active turn retain that turn's failure ownership; session cleanup errors are logged without inventing committed state.
- **Claimed turns have a bounded harness idle window.** `acp.ts` re-arms its 45-minute backstop on session traffic, including tool progress; open tools cannot disable it. Both turn loops discard a hung session. `turn-silence.ts` / `turn-silence-notice.ts` retry a `turn_backstop` once, then end with the failure line, including agent-triggered work. Coverage: `acp-liveness.test.ts`, `monolith-room-turn.failure.test.ts`, `turn-silence-notice.test.ts`.
- **Turn timing is daemon-side** (`turn-trace.ts`, JSONL under `<runtimeDir>/turn-traces/`), never in a Room.
- **Connect is the only onboarding flow** (`npx usebeeline connect`, `connect-command.ts`). It lists every supported harness, verifies the selected program before probing (`CONNECT_PROBE_TIMEOUT_MS`), and fails with its install command when missing; a deferring CLI joins Rooms only in `finishAgentConnectPairing`. Edit only `packages/usebeeline/README.md`; root `README.md` is a copy made by `npm run readme:sync`.
- **`@agent /login`** (Claude Code's `/login` at the call site, every harness; `agent-sign-in.ts` server + body): writes an `agent-sign-in` card; the helper runs one of four kinds (Claude paste-back PKCE, Codex/Grok device code, Cursor approve-and-wait, Pi/Goose/OpenCode provider key) and keeps every secret; a pasted code or key crosses the server only as a NOTIFY forwarder, never a row, card or log; link and device code are projected to the owner only. Shape drift: `*sign-in.contract.test.ts`.
- **Built-in `beeline:*` apps need no connection setup.** `connect` returns ready with an `app_tool` hint for their IDs and aliases, before external discovery or Squire provisioning. Tool execution retains its existing permission rules, including wallet and published corner-app rules. Boot withdraws stale pending `connection-install:beeline%` asks using the grant vocabulary’s `revoked` state and settles their cards.
- **Connectors.** `connector-squire.ts` owns Squire install/vault/revoke; `ConnectorUsageRecorder` sends one `postConnectionUsage` per turn. Squire has no `workspace_connectors` row: its agent tool probes the local task forwarder when mounted and otherwise uses its machine's broker report; Connectors shows each machine's broker report (`postConnectorVault`, `squire-machine.ts`). Vault metadata belongs to its owner and machine. For Squire app setup, `connect` checks the calling session’s mounted forwarder and owner consent, then returns a URL and goal for the agent’s own `operate_drive`; handbacks and saved-login approvals stay in Squire. A vault credential makes the app ready. Coverage: `read-only-mcp.workbench.integration.test.ts`, `workbench.integration.test.ts`, `squire-machine-status.browser.test.ts`. One host `trusty-squire-broker.service` elects; every other Squire spawn is the non-electing façade (`squire-broker-link.ts`). Squire's file credential store is not masked from agents. `PhoneService.readWorkbench` supplies one `companies` index for list, detail, search and summary (`workbench-companies.ts`, `company-registry.ts`). Usage/login hosts precede structured service/env-key aliases; labels never choose a company. The Squire sign-in service holds eligible personal computers only, and each credential lives once in its company; free-agent servers and Squire API app pointers are excluded while agent routes remain intact. Per-item detail/revoke/reconnect permissions remain authoritative. Server logo descriptors use bundled marks or bounded public-site icon fetching (`company-logos.ts`); the phone never guesses brands. Suggestions share this registry and the production-user cohort, excluding owned companies; missing apps live in company detail. Guards: `workbench-companies.test.ts`, `company-logos.test.ts`. Route order is in `app-connections.ts`.

- **Installed agent programs are authoritative.** Connect lists all supported harnesses and checks the selected program before probing. Runtime startup preserves missing-program install hints in Room receipts. Claude/Codex/Pi adapters receive the user program paths; adapter npm installs stay on `@latest` and omit optional bundled harness binaries. The daily feedback-triage adapter check uses no login or credential. Commands, overrides and proof: [installed agent programs](agent-programs.md).

## Lifecycle, commands and model selection

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

### ACP startup

- **ACP scopes bind to the helper's lifetime without ordering after its readiness.** `AcpResourceScope` (`apps/body/src/acp-resource-scope.ts`) keeps `BindsTo` without `After`: the notify helper can initialize ACP before READY, so ordering its scope after readiness can deadlock startup (`acp-resource-scope.startup.test.ts`).
- **Intake precedes retention work.** `room-runtime.ts` starts Room command loops and corner subscriptions, then reports serving before archived cleanup. Cleanup still yields watchdog progress and preserves unpublished work (`room-runtime.startup.test.ts`, `workloop-watchdog.test.ts`).
- **Native conversation memory survives helper restarts.** Codex/Grok Room and corner loops load the matching harness session and its delivered row IDs from private `agent-home/warm-transcript.json`. Configuration/checkout changes, failed native loads and the unchanged 30-minute idle boundary start cold; unsupported harnesses retain bounded transcript replay. Open Room storage preserves the resume record; archive removes it with the private home (`monolith-native-resume.test.ts`, `warm-transcript.test.ts`, `storage-bloat.regression.test.ts`).

### Tagged control commands

- **An exact tagged lifecycle command is server control, never a model prompt.** `routeHumanMessage` treats a whole message `@agent restart|status|stop|retry|debug|help|login` (or `@agent /restart`, `/login`) as control. Status/help follow access policy; debug/restart need the agent owner or a Room manager; stop/retry also allow the requester; login is owner-only. Restarts coalesce per agent in `agent_commands` until `ConnectionPresence` sees a new lifecycle id.

### Model catalog

- **A model picker is a live account verdict.** `apps/body/src/model-catalog.ts` offers only models proved through the startup-validation setter; the phone renders `agents.model_catalog` + `selected_*` verbatim (`model-catalog-sync.ts`). A failing persisted selection becomes `agents.model_unavailable` and the `wrong-model` silence line. Transient 429/529/timeout/auth-shaped failures are hiccups, never a model verdict (`isTransientProviderText`, `isAuthShapedFault`); a vanished id falls back within its family (`resolveModelFamilyFallback`).

- **Agent tool schemas stay compact.** `minimal-tool-surface.ts` declares the canonical ordinary tools; `read-only-mcp.ts` validates advertised schemas and maps only those tools to authorized internal operations; legacy names and input aliases are refused. Workflow, wallet, browser-share, corner-app and avatar schemas are discovered through `app_tool` first-party routes; no mid-session tool-list refresh is assumed. `room-session.ts` mounts repository/scratch fallbacks only when native IO is unproven, and Claude alone needs the explicit silent receipt. An offline Codex Room keeps scratch IO even with a native shell (`roomNativeIoProven` in `harness-capabilities.ts`). Measure exact descriptors with `npm run measure:agent-tools -- <output-dir>`; authority and privacy regressions live in `minimal-tool-surface.test.ts`, `commander.integration.test.ts` and `corner-lifecycle.test.ts`.
