# Project agent memory

Committed home for project-intrinsic agent knowledge: rule + authoritative file + coverage pointer. The named code and tests hold the detail; do not re-expand prose here.

## Core invariants (read first)

- **kind:30078 reads filter by `#d`, NEVER `#h`** (a `#h` filter over kind 30078 matches nothing). `agentPresenceKey(channelId)` (`packages/buzz-client/src/agent-presence.ts`) is the one presence-key builder. Generic relay stubs cannot catch this — use `matchesFilterRelayFaithfully`/`stubRelayFaithfulPublishing` (`packages/buzz-client/src/client.test.ts`). Source assertion: `agent-presence.test.ts`.

- **Local stack vs production:** `git-url.ts` maps `git://` markers to `https://`, unusable against the local docker stack (`relay-stack/compose.yml`, http 127.0.0.1:3010) — pair repo-less and invite top-level Rooms. Gate helpers resolve the relay from env AT IMPORT TIME; their package default is now the loopback stack, and explicit overrides must be set before importing `@beeline/gate`.
- **The phone has one write transport.** `BuzzRigTransport` (`apps/mobile/sources/sync/transport/buzz-rig-transport.ts`) is a stable public name for `MonolithRigTransport`; it has no runtime selector or relay/NIP-29 fallback, and callers pass only the identity. The `@beeline/buzz-client` HTTP bridge and `apps/gate` remain for the isolated relay stack, operator smoke/provisioning scripts, and legacy relay reads; they are not phone write transports. Coverage: `monolith-rig-transport.test.ts`, `room-view-client.test.ts`.

- **A phone closes a corner through `requestCornerClose`, never chat prose.** `PhoneService` locks current human Room/Workspace membership, routes the existing structured `stop` action to active assignments, and applies the same terminal state as daemon `archiveCorner` through `corner-close.ts`; the mobile screen navigates only after that operation succeeds. - **A corner operates as a Room: MEMBERSHIP is the authority, the branch is the shared artifact.** `DaemonService.corners` lists every corner the agent is a member of and `access` gates every corner write; `corner_facts.owner_agent_id` survives only as the historical "opened by" (`createdBy`, the phone's corner mark and card). `membership-join.ts` propagates a new/restored top-level Room membership to every existing corner in the same transaction; its deploy backfill adds only missing inherited rows, never resurrecting an explicitly removed corner member. `archiveCorner` alone stays with the opener (`assertCornerOpener`) — it is terminal for everyone's work; the merge webhook and a human close request still reach it. Each member helper cuts its OWN worktree from `origin/<feature_branch>` when GitHub has one (`materializeCornerWorktree`) and `corner-branch-sync.ts` rebases it onto that branch before every turn, raising `CornerBranchDivergedError` rather than clobbering a sibling's push. Conversational work is authorized only by `agent_commands` (`apps/server/src/agent-command.ts`): human tags/replies/DMs or exact agent tags in committed agent replies. Owner, opener, carrier, membership, and sender history never authorize a conversational turn. The server selects the lifecycle target for objective and changed check-state commands. A restored helper never re-announces `working` over existing PR/check lifecycle. **One check turn per changed server state, never per note** (`corner-checks.ts`): a completed check note starts ONE turn only when `getCornerRestoreState().lifecycle.checks` differs from the last turn's state; a checks-turn reply that only restates the notes is dropped (`isCornerStatusRestatement`), and a Room turn whose `open_corner` call succeeded settles silently — the server's corner card is the whole handoff, so no reply text is published (`monolith-room-turn.ts`, `monolith-room-turn.corner-echo.test.ts`). **A corner's wake is not its own noise (C106):** `corner-wake.ts` is the ONE predicate for what wakes an intake loop — a corner's Room id IS the corner id, so its own draft/thought/retract/presence/activity/receipt publishes land on the channel it waits on and are ignored, consecutive wakes held `CORNER_WAKE_MIN_INTERVAL_MS` apart. ## Server-indexed surfaces and Room reads

- **Room swipe means leave; DM swipe means dismiss.** For an ordinary member, the Room action confirms and removes that user's membership, which removes the row without deleting history; new Room traffic never rejoins them. Workspace owners/admins get an explicit cannot-leave explanation, never a fake close. A DM has immutable membership, so its action writes per-viewer `chat_dismissals`; `PhoneService.readChats` reports that DM closed only until newer inbound activity, and explicit DM resolution/navigation can clear it. Old Room dismissals are ignored. Coverage: server `integration.test.ts`, mobile `room-list-row.test.ts` and `channels.leave.test.ts`.

- **Workspace avatars outlive Room media.** `durable-avatar.ts` promotes a locally uploaded image in the `updateWorkspace` transaction into bounded `avatars` bytes (256px, <=128KiB), served at `/v1/avatars/<id>`. Old expired images are not recovered; choose them again. Person/agent photo overrides remain disabled. Coverage: `durable-avatar.test.ts` exercises TTL sweep plus fresh-session reads.

- **Helper intake is push-first, with exactly one slow reconciliation sweep.** `DaemonApiClient.liveSubscribe` requires the server's explicit Stage 4 capability acknowledgement before command intake uses the slow reconciliation interval; reconnect replay plus id dedupe remains the lossless recovery path. `ConnectionPresence` owns authenticated last-evidence presence: accepted daemon HTTP operations and lifecycle-bearing live subscriptions advance one monotonic `observedAt`; readers age online evidence out after 90 seconds. One evidence update changes one durable presence row and emits one PostgreSQL notification; each server listener reads that canonical body with current memberships once, then fans it to every joined Room in memory. Never combine per-Room durable rewrites with membership-expanded listener fanout: that is O(Room²). A one-shot mention deadline may demote only the exact evidence version it observed, so later authenticated contact or a turn receipt wins the race. Pending deadlines are recovered once from messages at startup/LISTEN reconnect, and maintenance retains last-evidence rows. SDK `agent-presence.ts` owns the same expiring online verdict. `BackgroundLeader` sleeps until the next schedule or a committed schedule notification and holds the advisory lock while firing; its 60-second pass is the single reconciliation net. Coverage: body `daemon-api-client.test.ts`, `monolith-corner-turn.test.ts`, `daemon-api-client.integration.test.ts`; server `connection-presence.test.ts`, `postgres-live.test.ts`, `production-latency.test.ts`, `agent-schedules.test.ts`, `background.test.ts`.

## Branch conventions

- **Corner agents own the GitHub workflow.** Finish means commit, push, `gh pr create`, print the URL, wait for the server checks-passed fact. With no human hold the agent merges with `gh`; the merge webhook archives and reaps the worktree.
- `fm/*` branches stack; check `gh pr list --json baseRefName,headRefName` before assuming a file is on `main`; `git branch -a --contains <commit>` finds the source branch.
- A cherry-pick off `feature/*` can drop a context-only declaration — `npm run typecheck` catches it. Generated `relay-stack/web/dl/` bundles are ignored; never stage them in a cherry-pick (the release-channel contract is in `docs/cli-bundle-channel.md`).
- **Resolve merges as one batch gate:** enumerate every textual conflict and semantic overlap first, resolve the complete set in one pass, then run one integration matrix plus a single conflict-resolution review before push.
- **`TYPECHECK` (root `npm run typecheck` = turbo + the isolated mobile app + `tsconfig.scripts.json`) gates every PR unfiltered by path** — the one gate with no path filter: two independently green PRs can merge cleanly into a red `main`, so a required-field change on a shared row type must re-run the root typecheck after merging `origin/main`.
- **Stacked PRs merged base-first do not propagate** — re-target to `main`; verify with `git grep <symbol> origin/main`.
