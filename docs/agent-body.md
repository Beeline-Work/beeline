# Body agent invariants

- **Corner outage recovery:** `retry-barrier.ts` bounds all coordinators' starts, including pushes, with jitter. `room-supervisor.ts` and `server-command-intake.ts` honor dated resets across discovery/reconnect wakes; rejected ACP requests park until a real configuration change. Keep stop/restart authority available while parked. `WAKE-STORM` regressions in `room-runtime.lazy-corners.test.ts`, `room-supervisor.test.ts` and `server-command-intake.test.ts` reproduce the storm. Evidence: [2026-10-27 incident](corner-restart-storm-2026-10-27.md).

- **The helper is a monolith-only thin Room client:** `ThinDaemonCore` → `RoomRuntimeCoordinator` → `MonolithRoomTurnLoop`, every operation through `DaemonApiClient`. Room and corner loops share `agent-home.ts`, `acp.ts`, `session-scheduler.ts`, model selection, persona delivery, bwrap spawning, and the agent MCP (`read-only-mcp.ts`).
- **One helper process per machine, one heartbeat-checked socket.** `beeline daemon --machine` (`machine-helper.ts`) hosts every agent in-process (`agent-runtime.ts`); an agent crash retries only that agent indefinitely (5 s doubling to 60 s); auth/configuration and other permanent 4xx startup refusals retain the error until a real revision or explicit start. The machine has only starting/serving/stopping states; its native supervisor restarts every exit unless explicitly stopped. The existing local watchdog tick asks every `ThinDaemonCore` to acknowledge work-loop progress before sending `WATCHDOG=1`; status and socket traffic never feed it (`workloop-watchdog.test.ts`, opt-in `workloop-watchdog.systemd.test.ts`). Non-retryable registration and socket-upgrade refusals park for the channel/link lifetime; archived-cleanup refusals persist across helper starts, preserve local code and branches, and reclaim only ignored generated output (`machine-link.refusal.test.ts`, `live-link.test.ts`, `corner-branch-sync.test.ts`). Established agents stay serving regardless of health prose; discovered surfaces without an observed fault do not imply degradation (`machine-helper.test.ts`, `surface-health.test.ts`). Heartbeats stop on permanent 4xx refusals (`turn-receipt-heartbeat.test.ts`). Helpers learn of work only through the socket (`no-polling.test.ts`): server pings every 30 s, the helper drops a socket silent for 75 s. Negotiated application checkpoints also wait behind server subscription and command work; missing checkpoints replace the machine socket within 105 s without reads ([incident and proof](helper-false-offline.md), `intake-link.integration.test.ts`). Room intake subscribes even during storage maintenance; ordinary claims wait for the lease, whose release wakes intake directly. Incident and restart regression: [Room restart recovery](room-restart-recovery.md).
- **Background tool completion is push-driven.** `AcpClient.sessionPrompt` retains unfinished tool IDs after `end_turn`; corner clients also negotiate Claude ACP's `asyncTasks` extension because a detached Bash tool call completes before its job. Terminal tool/task notifications call `postBackgroundToolCompletion` with the originating turn generation. The server creates one deduplicated continuation command retaining its order chain, and refuses cancelled or stale generations. `SessionLifecycle.hasBackgroundWork` protects the harness from idle/capacity eviction until completion. Corner conversation replacement retains the old runtime and its completion callbacks until tools finish, the corner stops, or a two-hour cap expires; the next conversation starts fresh. Terminal ACP guards still reject new permission requests but preserve existing tool completion tracking. This uses existing tool state, never job-size classification. Coverage: `acp-background-tools.test.ts`, `session-scheduler.test.ts`, `commander.integration.test.ts`. A pending `no_reply_needed` stays in its originating prompt until its MCP result arrives, including after harness `end_turn`; terminal calls never become background continuations (`SILENT-END-1` in `acp-background-tools.test.ts`, `monolith-turn-silent.test.ts` and `agent-command.integration.test.ts`).
- **Tool refusals are MCP `isError` results** logged via `tool-call-failure.ts`. Corner names (≤3 words) and objectives (≤24 words) are owned by `packages/api-contract/src/corner-text.ts`. Merge approval is head-bound (`corner_merge_approvals`: PR number + head SHA), never brief-revision-bound.
- **Top-level Rooms: read-only filesystem, unrestricted tools.** bwrap enforces the filesystem rule, not harness mode; `roomPermissionDecision` approves mounted MCP calls, plus shell and native read/search kinds when sandboxed (`harness-capabilities.ts`); native writes/edits remain refused. `ensureBwrapSandbox` remembers a failed install for 24 h. Permission decisions read tool identity, never wrapper shape (`read-only-policy.ts`). Without the sandbox, only native attachment reads are approved: every declared path must to stay inside this session’s `BEELINE_ATTACH_SCRATCH_ROOT/attachments` before and after realpath resolution; missing paths and escapes remain rejected (`attachment-permission.test.ts`).
- **Workspace assets, Room harness state.** `workspace-assets.ts` selects one machine + Workspace cache/AVD-metadata tree for every harness; ACP adapters use the operator-installed harness programs. No Workspace adapter or harness copies are installed; Room and corner launches keep the host adapter and share only caches. The Android SDK stays at its operator installation. `agent-home.ts` keeps each agent/Room's `HOME`, sign-in, config, sessions and plugin data at the existing path. Pending approvals remain server scoped by agent and Room. Codex's downloaded `cache` and `plugins/cache`, and Cargo `registry` are exact shared binds; Beeline adds no shared pip or Gradle override. Inherited toolchain settings pass through unchanged. `bwrap-sandbox.ts` masks the stable Workspaces and agents parents, then restores this Workspace's assets, this Room's home/cwd and only its required control file. The old `siblingAgentMaskPaths` remains for legacy private-layout turns. `credentialMaskPaths` still hides known operator credentials. Agents share one Unix account, so bwrap shapes ordinary path visibility and is not a security perimeter. A Room has private `/tmp`; keep rig runtimes under `$HOME`. `shared-asset-capacity.ts` applies a best-effort free-space floor and monitored private recovery reserve; private writes can race the monitor. Operator-only old-cache cleanup is in `startup-cleanup.ts`; its explicit apply command requires the helper to be stopped.
- **An agent can ask to isolate one shared cache category.** `request_shared_asset_isolation` in `read-only-mcp.ts` creates a pending `shared_asset` Agent Grant with a reason and Room card. Only a Workspace owner/admin or the agent's owner may approve or deny it; approval is standing, and the human grant ledger can revoke it. `workspace-assets.ts` selects the agent-private cache tree and `bwrap-sandbox.ts` applies exact binds from the next session; `session-config-fingerprint.ts` replaces a retained session after a decision or revocation. Categories are pinned in `agent-grants.ts`, never file paths.
- **Repository Rooms and corners get an exact-repository GitHub App token** (`getRoomGitHubToken`). Room sessions inject `GH_TOKEN`/`GITHUB_TOKEN` and respawn on token rotation; their filesystem stays read-only. The Room `gh` launcher gives an owner-selected personal GitHub connection precedence: Squire uses sealed HTTP; managed OAuth and registry MCP translate issue-comment creation to the connected provider tool. Automatic vault discovery alone does not select a personal account. Selection uses the latest connection route provenance, including verified owner completion of managed OAuth and authenticated owner opening of registry sign-in; disconnect/rediscovery does not restore historical selection. Existing tool authorization applies, and personal-provider refusals do not fall back to App credentials. `room-runtime.ts` installs a worktree-only credential helper for corners. Coverage: `room-github-auth.test.ts`, `monolith-room-turn.retention.test.ts`, `room-session.test.ts`, `app-connections.integration.test.ts`.
- **Corner writers own per-agent copies, never checkout locks.** `agent-corner-checkout.ts` gives each corner + agent private refs, index and files, with hard-linked immutable Git objects and warm dependencies. `room-runtime.ts` publishes an immutable repository seed atomically; setup and turns acquire no checkout or repository lock, and fetches update only private refs. Read-only assignments reuse the parent Room checkout with a read-only sandbox; a repository-work revision selects the writer's copy. Legacy shared files, index and unpublished HEAD are copied to the server's current implementer; the original remains recovery evidence. `syncCornerBranch` preserves dirty files and conflicting unpublished commits. A departing agent's published private copy and private Git directory are reclaimed without deleting the shared remote branch or needing revoked Room access; unpublished work and live processes remain protected. Coverage: `agent-corner-checkout.test.ts`, `monolith-corner-turn.test.ts`, `room-runtime.agent-checkout.test.ts`, and `scripts/prove-corner-checkout.mjs`. Corners share npm/pnpm caches. `dependency-generation.ts` prepares lockfile-keyed root/mobile dependencies at activation, including Workspace corners. `warm-node-modules.ts` shares package inodes; `bwrap-sandbox.ts` seals every dependency tree after writable parent mounts. Lockfile fingerprints replace retained sessions automatically. Store collection uses hardlink references during background maintenance and checkout cleanup, not an LRU limit. Dependency-store reuse never waits for another owner: warm copies continue, cold copies install privately, and busy collection/harvest is skipped (`dependency-generation.test.ts`). See [shared dependency generations](shared-dependency-generations.md). Permanent legacy archive refusals are recorded before optional preservation, and retention runs independently of discovery (`workloop-watchdog.test.ts`).
- **MCP launch settings stay out of harness arguments.** `AcpClient` replaces MCP declarations carrying environment values with a private launcher and owner-only files inside the session home (`mcp-launch-files.ts`). Only the MCP child receives those values; new and resumed sessions use the same boundary. Files are removed after session teardown. Never forward raw MCP environment values to an adapter: the Claude SDK serializes them into `--mcp-config`. Coverage and process-list proof: `mcp-launch-security.test.ts` (`TOKEN-ARGV-1`).
- **Imported MCP servers are `local` or `host`** (`mcp-route-class.ts`). A host server (Squire, or `beeline_route = "host"`) mounts only through an owner-approved `kind=mcp` route grant (`host-mcp-route.ts`). Squire uses one `SquireTaskRelay` connection per task (15-min idle lease) through the host broker.
- **Squire approval deadlines are lease bounds, not human decisions.** The forwarder clears a vault wait when `credential_fetched` returns without a URL, keeps retries correlated to the original requester, and fences pending responses racing an authoritative decision. Only Squire decision notifications wake the requester; elapsed local timers release tracking without inventing “no answer.” Vault calls have a 30-second transport deadline; browser calls retain their 210-second ceiling. Coverage: `squire-task-relay.test.ts`, `squire-mcp-client.test.ts`, `resource-mcp-facade.test.ts`; incident and matching proof: [late credential approval](late-credential-approval-proof.md).
- **Live Squire shares span model turns.** `squire-share-renewals.ts` renews `operate_share` on the session's owning connection and updates only matching live rows through `refreshComputerSession`; it does not extend the forwarder's idle lease. `computer-session.ts` treats an old upstream deadline as a liveness check, and consumes main-frame `navigation` notifications while the human controls the browser. Requires Squire 1.1.33. Coverage: `squire-share-renewals.test.ts`, `squire-task-relay.test.ts`, `computer-session.test.ts`.
- **Attachments reach the harness as content, never a URL** (`attachment-delivery.ts`): images go inline only when the harness (`promptCapabilities.image`) and the model (`openrouter-routing.ts` pins `input_modalities`) accept them. Only the message being answered is pre-downloaded; other transcript messages show `📎 name (type, size) id=<media id>` markers (`attachmentMarkerLines`) and `download_attachment` (`read-only-mcp.ts`) fetches one on request under `getRoomMessage` authority, sha256-deduped, with typed `not_found`/`forbidden`/`too_large`/`download_failed` refusals.
- **Artifact reports wait for delivery preparation.** `callAgentTool` registers `post_artifact` work before yielding and waits for earlier uploads and attachment queueing before `report`. Upload or queue failures block reports and explicit posts until a later artifact successfully uploads and queues a replacement with the same attachment name; the next request/generation starts fresh. Orders, reports and posts refuse private local paths, including foreign home and temp paths; use attachment names after posting an artifact, or carry the file in the target corner brief. Explicit posts wait for in-flight uploads and bind queued files immediately in the current place. Coverage: `read-only-mcp.report.test.ts` and the built MCP → daemon → delivered-message proof `ARTIFACT-REPORT` in `commander-recovery.integration.test.ts`.
- **`post_artifact` path roots** are the checkout plus the agent's whole writable session home (`BEELINE_ATTACH_SCRATCH_ROOT`), checked by `resolveAttachPath`; `scratch_io(action:write)` writes only there. `helper-storage.ts` replaces the private scratch TTL sweeps: confirmed archive immediately removes whole private Room folders (local conversations included; server messages retain the transcript). Open surfaces preserve credentials, settings, browser profiles and harness conversation/resume state. Disposable private files and npm/turbo cache files expire independently after seven days; recent siblings and directory timestamps cannot pin old bytes. Model/tool generations and code copies retain whole-object publication/use checks. Scheduler leases fence Room and machine cleanup; processes, open files, mounts and emulator leases defer it. `storage-owners.ts` removes ended agents and the last local Workspace's assets, persists deferred cleanup authority, and identifies legacy checkout owners by the Room/remote/branch hash. Archived checkout facts persist independently of revoked Room access. A confirmed landed PR head permits local cleanup after squash merge; genuinely dirty/unpublished work remains protected. Shared checkouts retain publication guards. Trusty Squire stores are hard-excluded everywhere; tracked `skills/trusty-squire` is source code. `storage-filesystem.ts` repairs owned read-only download directories only during removal. Linux inventory streams `/usr/bin/python3` output with `O_NOATIME`; macOS uses native filesystem inventory, `lsof` and `mount`. Neither follows symlinks; unavailable process/filesystem evidence fails closed. `beeline storage --dry-run` / `--orphans` and `npm run dry-run:helper-storage` make only authenticated reads and inventory, without helper lifecycle actions or credential write-back. Unlisted private Rooms use seven-day disposable-file expiry without synthesizing an archive; failed lifecycle reads retain storage. Unknown lifecycle is reported separately from confirmed orphans. Coverage: `storage-bloat.regression.test.ts`, `helper-storage.darwin.test.ts`, `helper-storage.test.ts`, `storage-lifecycle.integration.test.ts`, `room-runtime.archive-cleanup.test.ts`. Machine evidence and causes: [storage bloat investigation](beeline-storage-bloat-root-cause.md).
- **Harness quirks.** pi ignores `session/new` `mcpServers`, so `pi-mcp-bridge.ts` writes an extension before spawn. `piHasNativeMcp` must probe with the session's own `agentEnv` (`PATH` above all), never this daemon's `process.env` — pi-acp resolves its own `pi` child against the former, and the two can name different installed Pi versions. pi-acp also forwards a Pi extension's `ui.notify()` (e.g. the bundled `mcp` extension's "servers need attention" warning) as an `agent_message_chunk` tagged `_meta.piAcp.notify`; `acp.ts`'s `agentMessageChunkText` must keep treating that as non-text so a harness infrastructure notice can never stand in as the agent's reply. Cursor speaks ACP through `cursor-acp-bridge.ts` (never `cursor-agent-acp`); its login is `~/.config/cursor/auth.json`, linked by `agent-home.ts`; the helper unit PATH includes `%h/.local/bin`. claude-agent-acp `settings` must be an object (`harness-tool-scope.ts`). `meaningfulHarnessStderr` filters pi's harmless `-32601` dump.

Missing/unreadable journals resend conservatively. This applies to Rooms and corners; task text and attachment blocks remain intact. Regressions: `pi-session-instructions.test.ts`; ACP transport/token proof: `scripts/prove-free-agent-instructions.ts`.

Package/bin metadata must match the actual executable (including `PI_ACP_PI_COMMAND`); unrecognized executables get a bounded background version probe. Restore the original `NODE_OPTIONS` before Pi or tool children start. The rewrite is atomic: changed anchors or missing adapter bindings load the original source unchanged, preserving startup at the cost of synchronous informational checks. Coverage: `pi-startup.test.ts`; [Fly timing and cleanup proof](pi-startup-cut-proof.md).

The lease owns its adb server at console port plus two; `prepareCornerAdb` restores that server and `ANDROID_SERIAL` on later turns, and its adb launcher resolves the kept record on every call, including a boot during the current turn. Host-granted commands inherit that launcher PATH too, so a sanitized command environment cannot bypass the record and use a stale per-agent server (`emu-1` in `monolith-corner-turn.test.ts`). A second start reuses that device without adding a duplicate TCP transport. Corners without a lease retain the per-agent wiring in `android-agent-env.ts`. Closing a lease stops its adb server too. Proof: `scripts/prove-corner-adb.mjs` boots concurrent isolated corners against the installed SDK. The helper stops it when the corner closes, lands, or archives, and on helper start when the corner is confirmed gone. The legacy private layout still uses `android-agent-env.ts`. Agents share the uid and network, so explicit adb connections can still reach another emulator. Approved `/dev/kvm` grants also probe the host device and attempt an exact helper-user ACL without sudo (`kvm-device-access.ts`); an unprivileged helper reports the host repair in [KVM access](android-kvm-access.md). Emulator boot failures return the diagnostic log before cleanup (`corner-emulator.test.ts`).

Supervision of stalled corner work comes from corner state transitions (idle alert, waiting-on-human states); Room-addressed orders get no fallback alert. The helper's explicit `unreported_order:` failures (repeated-call guard, free-agent time limit, login required) still use the failed receipt → `noteFirstSilence` → `reportToCommander` route, unless the generation already reported or recorded a durable child/approval continuation. Reports from closed corners are discarded. Other reports follow recorded opening ancestry to the nearest live return place while retaining commander membership checks; report/lifecycle final prose does not automatically re-answer an order that already has an outcome. Informational wakes can still end quietly; cancellation and stale generations retain their fences. Coverage: `commander.integration.test.ts`, `turn-silence-notice.test.ts`, `monolith-room-turn.failure.test.ts`, `acp-liveness.test.ts`. Squire decision publication failures during an active turn retain that turn's failure ownership; session cleanup errors are logged without inventing committed state.

Background scan yields cannot acknowledge a frozen foreground discovery; idle cores answer the existing local watchdog wake without server reads (`workloop-watchdog.test.ts`). ## Lifecycle, commands and model selection

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

### ACP startup

- **Failed activation owns its harness cleanup.** Room and corner loops stop an unusable prior client before replacement, and discard the new client if cold activation fails, including after session creation. Native resume failure still falls back on the same client. The explicit ACP `-32000 Authentication required` refusal produces a terminal `not-signed-in` receipt; provider refresh races retain bounded hiccup retries. Regression and real subprocess proof: `monolith-activation-failure.test.ts`.

- **ACP scopes bind to the helper's lifetime without ordering after its readiness.** `AcpResourceScope` (`apps/body/src/acp-resource-scope.ts`) keeps `BindsTo` without `After`: the notify helper can initialize ACP before READY, so ordering its scope after readiness can deadlock startup (`acp-resource-scope.startup.test.ts`).
- **Intake precedes retention work.** `room-runtime.ts` starts Room command loops and corner subscriptions without awaiting pending legacy migration; archived cleanup runs in the background and preserves unpublished work. Repository repair runs on the first fetch of an active cache, without scanning archived object stores at startup (`room-runtime.startup.test.ts`, `workloop-watchdog.test.ts`, `repository-cache-repair.test.ts`).
- **Native conversation memory survives helper restarts.** Codex/Grok Room and corner loops load the matching harness session and its delivered row IDs from private `agent-home/warm-transcript.json`. Configuration/checkout changes, failed native loads and the unchanged 30-minute idle boundary start cold; unsupported harnesses retain bounded transcript replay. Open Room storage preserves the resume record; archive removes it with the private home (`monolith-native-resume.test.ts`, `warm-transcript.test.ts`, `storage-bloat.regression.test.ts`).
- **Codex context blocks are session scoped.** Verified structured-instruction adapters send rules at session creation and omit unchanged warm-turn blocks. Cache misses, native loads, failed delivery and compaction restore full delivery; other adapters retain their existing behavior. Version guard, proof and token measurements: [Codex prompt delivery](codex-prompt-delivery.md).

### Tagged control commands

- **An exact tagged lifecycle command is server control, never a model prompt.** `routeHumanMessage` treats a whole message `@agent restart|status|stop|retry|debug|help|login` (or `@agent /restart`, `/login`) as control. Status/help follow access policy; restart, stop, retry and debug are open to anyone in the Room (debug reports only this Room's turn); login is owner-only. Restarts coalesce per agent in `agent_commands` until `ConnectionPresence` sees a new lifecycle id.

### Model catalog

- **A model picker is a live account verdict.** `apps/body/src/model-catalog.ts` offers only models proved through the startup-validation setter; the phone renders `agents.model_catalog` + `selected_*` verbatim (`model-catalog-sync.ts`). A failing persisted selection becomes `agents.model_unavailable` and the `wrong-model` silence line. Transient 429/529/timeout/auth-shaped failures are hiccups, never a model verdict (`isTransientProviderText`, `isAuthShapedFault`); a vanished id falls back within its family (`resolveModelFamilyFallback`).

- **Agent tool schemas stay compact.** `minimal-tool-surface.ts` declares the canonical ordinary tools; `read-only-mcp.ts` validates advertised schemas and maps only those tools to authorized internal operations; legacy names and input aliases are refused. Workflow, wallet, browser-share and avatar schemas are discovered through `app_tool` first-party routes; no mid-session tool-list refresh is assumed. `room-session.ts` mounts repository/scratch fallbacks only when native IO is unproven, and Claude alone needs the explicit silent receipt. An offline Codex Room keeps scratch IO even with a native shell (`roomNativeIoProven` in `harness-capabilities.ts`). `revise_corner(action:brief)` accepts a complete brief projection copied from `read`; Body discards returned metadata and the server resolves approval and files again. Schedule updates/deletes still require a turn started by a human Workspace admin of the schedule’s Room; scheduled wakes are refused. Schedule prompts are bounded to 2,000 UTF-16 code units and report text to 16,000. Proof: `node --import tsx scripts/prove-tool-description-contract.mjs` after building Body and server (R1/R2). Measure exact descriptors with `npm run measure:agent-tools -- <output-dir>`; authority and privacy regressions live in `minimal-tool-surface.test.ts`, `commander.integration.test.ts` and `corner-lifecycle.test.ts`.

Reviewer prompt targets use one live `getPrChecksStatus` read per wake, plus the current brief and local git head. A stored pending lifecycle cannot override live passing checks; a mismatched checkout or unavailable provider read gives an unverified-target instruction, never a claim that GitHub checks failed. Coverage: `monolith-corner-turn.test.ts`, Reproduction `stale-green`.
