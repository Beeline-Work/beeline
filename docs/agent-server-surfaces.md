# Server-indexed surfaces and Room reads

- **Deliberate silence survives every harness.** `no_reply_needed` calls `markAgentTurnSilent` to persist `completion_kind='no-reply'` before acknowledging, without completing the command or revoking in-flight write authority; `postAgentTurnReceipt` preserves it. `DaemonService` acknowledges and discards later final text for that turn before public insertion or private report routing, including the atomic reply path. Whole final silence declarations (for example, “I posted nothing” or “Nothing to post”) also settle as no-reply; `no-reply.ts` owns the bounded grammar and preserves substantive answers. The generation and cancellation authority checks still apply. Coverage: `agent-command.integration.test.ts` and `commander.integration.test.ts` (`Reproduction R1`). Closing prose after an explicit post to the same place and turn generation is retained as a Turn summary activity note, rather than a second conversation message; posts elsewhere do not suppress it.

- **Voice uses existing agent identities and ordinary orders.** `apps/server/src/voice-service.ts` owns membership and dispatch; `voice-room-runtime.ts` speaks command-provenance reports without capping real work. Short-press dictation remains separate. Providers, native runtime requirements and isolated proof commands: [voice mode](voice-mode.md).

- **Computer activity is an observation, never an owed reply.** `computer-session.ts` retains Squire's preview channel, HTML and latest frame while any viewer remains; `ComputerSessionCard` preserves that preview's token when opening the full view. `agent-command.ts` coalesces one pending observation per share behind other work and refreshes its source at claim; Room/corner turn loops accept silence, and `turn-silence-notice.ts` never retries or inscribes an activity failure. Coverage: `computer-session.test.ts`, `server-command-intake.test.ts`, and the Room/corner turn tests.
- **Shared browser links enter through Beeline.** Point people at the live browser card. `browser_share start` returns its message id as `cardId`, its source session id for ending the share, and a plain instruction to open the card posted in this place. It returns no URL; the raw `/s/<id>/` address offers web and app entry without disclosing session metadata. The app obtains a viewer token with `openComputerSession` after sign-in. Tokens and current Room/agent authority still gate the viewer.
- **Computer share upstreams are allowlisted.** The server fetches and tunnels to a share's upstream URL, so `createComputerSession` accepts only `body:` or an `https:` URL whose host is under `*.trycloudflare.com`, the host Squire `operate_share` returns. IP literals, `localhost` and `.localhost`/`.internal`/`.local` hosts fail. Coverage: `computer-session.test.ts`.

- **Server-indexed surfaces are the only durable read authority.** `apps/server/src/phone-service.ts` owns paint-ready queries; `packages/api-contract/src/phone.ts` owns DTOs. Screens render validated responses as-is; a live event only marks a surface dirty. Never restore client reducers or snapshots.
- **A Room GET does not carry child corners.** `PhoneService.readRoom`/`RoomView` stop at the Room; corners come from `RoomViewClient.corners`, and the chat list's `cornerCount`/`openCorners` feeds `DesktopRoomCorners`. Opening a Room makes one live subscription (`useRoomSurfaceSession`); never expand watch-filter keys into per-corner subscribes.
- **A Room payload is projected, never all-or-nothing.** `readRoomView` (`phone-guards.ts`) fails only on a missing `room.id` or `messages`; unreadable optional fields are absent, never invented; unknown `role` reads `member`; `repositoryResolution` reads `unverified`.
- **Composer status is server-owned.** `RoomView.pendingAgentCommands` and the send ack show `Waiting for @agent` from an accepted human command until claim; `RoomView.latestAgentTurns` shows working from committed command dispatch, before helper acknowledgement. A reserved `pending:<command id>` generation clears after 90 s without pickup; a real helper claim replaces it in the same row. Optimistic turns do not prove helper presence. Real working turns remain visible until terminal state or 90 s without a receipt. `renudgeStrandedPendingCommands` re-pushes an idle helper's pending commands on connection and reconnect through the existing live trigger. No phone timer or presence guess drives either line. Room `agentState` is the max of its own and its open corners' (`CHAT_LIST_SQL`). Stop is allowed for anyone who may act in the Room (`cancelAgentTurn`) and shown only by `TurnProgressLine.tsx`.
- **A human Stop drains the stopped sender's existing queue.** Phone and tagged Stops share the Room/agent claim lock (`lockAgentCommandQueue`) and cancel pending orders from the same sender and source Room/corner up to the Stop transaction timestamp (`dropQueuedOrdersForStop`). Other senders, human mentions and later orders survive. The Stop line gives the queued count and one private report returns to the sender in the same transaction. Coverage: `agent-command.integration.test.ts`; set `BEELINE_STOP_TEST_POSTGRES_URL` to an isolated loopback PostgreSQL to exercise the concurrent claim and order-arrival proof.
- **Drafts.** Top-level Room `postAgentDraft` is a successful no-op (C109, `DaemonService.liveOutput`); corners store and publish drafts. Draft rows key on agent + request (`draft-settle.ts` `liveDraftRowId`), anchored at the turn's first snapshot. `LiveHub` reaches only listening sockets, so `PhoneService.liveDraftSnapshot` hands a late subscriber the current draft once. `turn-stream.ts` (`AgentTurnStream`) owns the bounded draft lane and one durable reply; corners also keep narration.
- **An ordinary final reply commits in one statement.** `DaemonService.postRoomMessage`'s no-mention path does authority, attachments, turn settlement, insert, command completion, draft cleanup and offline-notice withdrawal in one CTE (`daemon-service.completion-latency.test.ts`). Agent-to-agent hops count from `triggerMessageId`; the third hop persists without a delivery mention.
- **Server commands are the only helper work authority.** `agent-command.ts` stores `input`/`resume`/`stop`; `server-command-intake.ts` claims them; agent tags in a committed reply dispatch in the same statement up to depth 3. `getDaemonBootstrap.pendingRooms` binds waiting surfaces before reconciliation cleanup (`room-runtime.ts`). `commandRecoveryCtes` keeps the newest pending wake per Room on return, quotes superseded text as history, and fences stale workflow attempts at delivery and claim; fresh online traffic keeps its queue. Isolated startup replay: `npm run measure:fast-resume -w @beeline/body`. Conversation windows (`RoomConversationInput.window`, `warm-transcript.ts`) are context, never authority.
- **Silence and failure.** `noteFirstSilence` (`turn-silence-notice.ts`) owns silence/failure episodes, phrased by `packages/api-contract/src/turn-silence.ts`. Hiccups reopen the command (≤3 attempts, one give-up line); standing conditions complete it; transient corner-start failures stay pending. Committed replies suppress delayed failure handling before reassignment and again under the silence lock; automatic private failures include the place name and id. Corner unreachable reports also honor real turn and activity evidence since the wake, excluding optimistic `pending:` turns (`commander.integration.test.ts`, `turn-silence-notice.test.ts`).
- **A one-human, one-agent Room accepts untagged human messages.** `soloRoomAgentSql` (`agent-command.ts`) counts current active Room memberships inside the existing phone write/access and routing reads; no extra membership round trip. Only top-level non-DM Rooms qualify, and any typed mention suppresses the inferred target. Routing reuses the DM/tag target loop, access policy and deduplicated commands; corners, multi-human/multi-agent Rooms, System messages and agent messages retain their routing. Coverage: `solo-agent-routing.test.ts` (phone send → command claim → reply → Room read) and `agent-command.scaling.test.ts`.
- **Mentions are read, never stored.** `message-mentions.ts` (`resolveCurrentMemberMentions`, SQL twin `taggedIdentityIdsSql`) matches exact current handles against current Room membership. `agent-access.ts` alone decides who may address an agent; `noteUnansweredMentions` writes one line per reason (not a member, policy, offline after 90 s via `pending_mention_notices`). At most one push per recipient per agent turn (`background.ts`).
- **Live fanout crosses machines through PostgreSQL.** `postgres-live.ts` owns id-only triggers and a session `LISTEN` (`DATABASE_LISTENER_URL` when the main URL is pooled). The phone holds one `LiveConnection` and paints committed rows from their deltas, reading only what no delta describes.
- **Idle phones do not poll.** `LiveConnection` sends one tiny ping every 20 s while foreground, allowing 10 s for an answer. A silent socket is replaced with backoff on repeated failures; its fresh subscription causes one covering Room read. Background sends no liveness traffic. No working-Room reload timer remains. Failed Room refreshes still retry at 1/2/4 s, at most three times. Coverage: `live-connection.test.ts` and `useRoomSurfaceSession.silent-socket.test.ts`. Other reads follow live frames, reconnect, foreground, push or the viewer's own action. A Room's push hold is a `viewing` frame on that socket; `PhoneViewing` ends it when the socket closes.
- **A read never announces itself.** `QUIET_PHONE_OPERATIONS` (`server.ts`, over `PHONE_READ_OPERATIONS`) publish no Room invalidation: phones reread on one, so a read that announced it (`listRoomWorkflowRuns` in a corner) looped.
- **Mobile storage and reads.** `surface-storage.ts` persists only response + outbox partitions; cold open installs invalidation, then one signed GET. Read marks are server-owned (`room_read_marks`; `RoomView.viewer.readCursor`). `buildReplyCommand` (`reply-command.ts`) alone writes `h`/`e` tags.
- **The Needs-you tray is a server projection** (`apps/server/src/needs-you.ts`): a cell is a message that tags the viewer and asks (ends `?` or says please/approve/feedback), or a pending approval card the viewer can decide (`APPROVAL_QUERIES`: grant, write access, question choice, connector offer, sign-in, Trusty Squire), each filtered by its decide operation's own authority rule. Needs-decision reports and `ask_choice` accept an optional plain one-sentence `ask` (≤140 characters), with automatic extraction when omitted; reports store it in message card metadata and system approval writers generate it (`tray-approval-ask.ts`). The tray renders the server's plain ask; legacy rows choose a question or the first report sentence, strip markdown and shorten hashes, preserving the start. Coverage: `needs-you.test.ts`, `commander.integration.test.ts`, and Tray's `tray-ask-1` Chrome proof. Badge/bootstrap reads use `markSeen:false` and never start expiry. The visible Tray batches viewable unseen question ids into `markNeedsYouSeen`; its idempotent server acknowledgement starts the clock and returns expiries without another read. Legacy list reads still mark seen by default. Questions leave on tap/dismiss, a later viewer message, or 24 h after first paint; approvals leave on explicit tray dismissal, decision, expiry or close. Inline tray actions reuse `decideAgentGrant`, `decideWritePermission`, `answerChoice` and `skipChoice`; scripts and option consequences stay visible. Squire approvals open their own ceremony directly from the tray, while the source link opens their @System message. Dismissal never decides. Squire expiry is stored on its card; `backfillSquireApprovalExpiry` closes legacy stale cards.
- **Presence recovery bounds candidates before resolving tags** (`ConnectionPresence.observe`, `PushDeliveryLoop.runOnce`); inlining the tag matcher exhausted production pools in v0.0.95.
- **Room joins go through `membership-join.ts`.** Sign-in and `migrate()` create no membership; a person with no Workspace lands on create-or-join. `createWorkspace` makes a public `#general` (`first-room.ts`). An explicit join writes one `member-joined` note; a Workspace arrival retains its membership records without a System DM or broadcast push. Corner access derives from the parent Room with no copied membership writes. A Room membership change refreshes owed items once over indexed child-message candidates, including forwarded cards and reports (`corner-owed.ts`); never issue one refresh per corner. Production-sized invite proof: `invite-join-deadline.test.ts` with an isolated loopback `BEELINE_INVITE_TEST_POSTGRES_URL`.
- **First entry goes from sign-in to Workspace creation to #general.** Beebee’s first message teaches Room replies, corners and shared connectors without a repository card. Cards are offered on coding or GitHub-connection intent, never on Workspace creation or joining. Identity editing stays in Settings; the legacy welcome-card flag is unused by clients.
- **Repository workflows** in the phone UI are dispatched only by human Workspace managers (`listRoomWorkflows`/`dispatchRoomWorkflow`, exact-repo token, stored default branch). Production releases use the authenticated agent form of `dispatchRoomWorkflow`: active turn and human-root provenance are required, an audit receipt is committed in the place, and attribution is sent to GitHub. See [release pipeline](release-pipeline.md).
- **Reviewer sign-in.** `apps/server/src/review-access.ts` owns the store reviewer identity and `BEELINE_REVIEW_SECRET` (constant-time compare, rate limited, misses 404); entry is only the `/review/` link.
- **Machine disconnects stay silent.** `connection-presence.ts` records release/claim state in `agent_connections` and `live_outputs` without a System DM or push. Offline corner wakes remain queued silently (`machine-offline.test.ts`). A free starter agent is never offline: its released connection stays reachable and its wakes start its Fly Machine ([free agents](free-agents.md), `free-agents.test.ts`).

- **Agent members reads expose assignment facts only within the Room.** `listRoomMembers` extends owner/host metadata with selected model, reported billing, remaining provider windows (fractions plus reset times), key dollars or credits, free token allowance, and parent Room primary/fallback reviewer roles (`agent-member-metadata.ts`). Unknown billing or allowance stays absent; snapshot timestamps preserve age. The workspace roster keeps only public metadata. Coverage: `agent-member-metadata.test.ts`; isolated dispatch and roster proof: `npm run prove:no-self-review`.
