# Helper usage ownership

The negotiated `usageAccountV1` helper path publishes one provider account snapshot per canonical source revision. The private owner partitions sharing by origin, server-authenticated owner, provider and account identity. The publisher attaches itself; siblings send a small account reference once instead of posting another full snapshot. Per-agent context and key spend remain separate data.

`BEELINE_NETWORK_ROUTER_V1` is the single temporary router setting, off by default. A registration advertises support independently from overlays and read projections. A successful server registration supplies the actual owner, connection ID and connection epoch. A provider read captures that source before its first yield; a late result after owner or connection change cannot become a new owner's observation. The server checks the expected owner, locks the current agent and connection records, recomputes the source hash and commits the data with its revision. The reference revision is bound to the owner/provider/account partition. Account identity columns are immutable.

All selected usage writes use bounded request/reply on the existing authenticated AgentChannel. There is no second socket or HTTP fallback after selection. A sent timeout remains uncertain and cannot schedule another request. Context/key-spend posts carry a monotone actor revision; the source head and snapshot effect commit together. Older counters are ignored, an identical replay makes no effect, and a reused counter with different data conflicts. A refused or duplicate source cannot announce a fresh refresh completion. Identical context values join the existing write.

Legacy helpers may still post through the original HTTP operation. An actual legacy account-body change invalidates the prior bound source revision and advances source freshness evidence. An old reference cannot then attach under the previous revision, and an older new-helper snapshot cannot overwrite the later source. This is an explicit mixed-version cohort, not an assumption that old helpers enforce the new protocol.

The server emits complete canonical `AgentUsageCell` values, independently of profile and Workbench DTOs. A private cell contains an owner partition, generation and monotone revision. Ownership refusal is content-free. The existing journal and LISTEN connection capture actual account, context and ownership changes; an idle subscription does no work. Connection initialization obtains a control cut only. A focused read obtains the small cell, and actual committed sources deliver subsequent changed cells. The final enqueue holds the real agent ownership row lock. The server never requests a client's held cache or pass inventory.

Proofs live in `helper-usage-publisher.test.ts`, `helper-usage.integration.test.ts`, `helper-usage-socket.test.ts` and server `helper-usage.test.ts`. They use synthetic provider output, storage and sockets. Real PostgreSQL competing-writer/final-owner proofs and released helper/phone cohort proofs remain enablement requirements; these unit and PGlite proofs do not establish them.
