# R1: open pull request refusal in the corner sheet

## Production reproduction

The owner tapped Close corner on settings-flow-prototype
(`500f6c94-376b-4eed-a9b6-1f05059e558f`), with PR 2741 open, an active
owner merge hold and the corner unlocked.

Fly production logs for `beeline-server`, read through the owner's vaulted
org-deploy connection, show:

```text
2026-10-22T02:05:12.699174732Z [req] POST /v1/phone/operations/requestCornerClose
2026-10-22T02:05:12.729742514Z [req-error] POST /v1/phone/operations/requestCornerClose status=409 Error: close the corner pull request with close_corner_pr before closing the corner
```

The request runs `PhoneService.requestCornerClose` → `closeCornerState`.
The latter refuses an unmerged recorded PR before cancelling commands,
archiving the room or queuing branch deletion. The phone transport wraps that
response in `MonolithPhoneOperationError`. The chat callback previously showed
its diagnostic `.message` verbatim:

```text
Monolith requestCornerClose failed (409): close the corner pull request with close_corner_pr before closing the corner
```

The Sentry organization issue search for last-seen times between
02:04:00 and 02:06:59 UTC returned no issues. The server reports unexpected
failures to Sentry; this expected conflict remains a request log.

## Demonstrated

The sheet now shows:

> This corner still has an open pull request. Ask an agent to close the pull request, then try closing the corner again.

The server's close policy is unchanged. This implements the brief's refusal
alternative; it does not automatically close the PR or remove the hold.

The production corner was not closed or otherwise mutated for this proof.
Instead, the server integration creates the matching state and verifies that
the refusal preserves the PR, lock, hold and unarchived room, without queuing
branch deletion or calling GitHub to close/delete anything.

The browser stand-in builds the shipped close callback, real phone response
parser, action row, modal manager and alert dialog. A click receives the exact
production response and renders the plain explanation in the dialog at phone
width. Only the network response and device services are substituted; this
is not an Android device or a full chat-screen demonstration.

The callback regression was also run with its original error rendering restored:
it failed because the alert contained the raw Monolith diagnostic. Restoring
the fix makes the same case pass. Additional cases preserve other refusal
reasons and navigation after a successful close.
