# Body agent invariants

- **A closed connection is the only reconnect trigger.** `live-link.ts` owns the machine socket and uses OS TCP keepalive; it has only connected/disconnected states. Discovery failures, refused requests, turn deadlines, initial snapshots and local progress never replace it. `room-supervisor.ts` waits for the next authenticated open after intake failure. Coverage: `intake-reconnect.test.ts`, `helper-operation-socket.test.ts`, `machine-link-recovery.test.ts`.

- **Helper claims bind the authenticated machine connection.** Every claim carries its connection ID and epoch. `connection-presence.ts` returns that connection's claimed commands to pending on close and recovers pre-upgrade ownerless helper claims at registration, preserving MCP claims; it never manufactures a terminal turn from silence. `HelperTurnChannel` retains only generation ownership bookkeeping. Requests keep their IDs through socket loss and read their original results on reconnect; effects are not blindly replayed. Coverage: `helper-turn-channel.test.ts`, `agent-command.integration.test.ts`, `machine-connection-drop.test.ts`.

- **The helper is a monolith-only thin Room client:** `ThinDaemonCore` → `RoomRuntimeCoordinator` → `MonolithRoomTurnLoop`, every operation through `DaemonApiClient`. Room and corner loops share `agent-home.ts`, `acp.ts`, `agent-process.ts`, model selection, persona delivery, bwrap spawning, and the agent MCP (`read-only-mcp.ts`).
- **Agent processes have one owner and no capacity ceiling.** `agent-process.ts` starts a harness on work, serializes turns within a conversation, and stops it after one configurable stay-warm countdown from its last completed work. New work cancels that countdown; there is no sweep, suspend/resume, LRU or slot wait. `AcpClient` has no request, silence or free-agent deadline timers. Process loss sends a `process-exited` interruption receipt; the server retains the command and intake re-reads it only when another message/order/schedule arrives. `/restart` retires harnesses while subscriptions keep serving. The setup wizard's RAM/CPU estimate warns without blocking. Architecture's `helper.agent-process` rule owns ACP start/stop calls; coverage: `agent-process.test.ts`, `acp-process.test.ts`, `server-command-intake.process.test.ts`, and the planted caller in `scripts/architecture-invariants.test.mjs`.
- **Daemon operation dispatch has one owner.** Every runtime operation uses `AgentChannel.requestOperation`; callers cannot acquire transport capabilities (`scripts/router-boundaries.mjs`, mutation tests in `router-boundaries.test.mjs`). The private HTTP adapter serves explicit one-shot repository credential readers only. Server HTTP ingress remains for installed older helpers and sandboxed tools, sharing `DaemonService` authorization. Operations run independently of the serial intake queue so external work cannot block Stop/subscriptions. Coverage: `helper-operation-socket.test.ts`, `daemon-live.test.ts`.

- **One machine handshake, all agents and capabilities.** `machine-helper.ts` hosts agents in-process; `machine-link.ts` registers them together and each Room reads its messages/commands and setup once on authenticated reconnect, then receives pushes. The native manager restarts an exited helper; there is no systemd watchdog or application heartbeat/pong timer. Server machine output and login/version changes belong to `machine-connection.ts`; request failure and backpressure cannot close it. `scripts/check-architecture.mjs` runs the AST connection boundary and its shrinking sink inventory. Helper timers are banned; the sole named exception is the stay-warm countdown in `AgentProcesses.workChanged`. Local waits follow actual filesystem/process/connector events. Free-agent idle sleep is server-owned; browser shares renew only on viewer activity. Proofs: `scripts/machine-connection-boundaries.test.mjs` plants forbidden reconnect/timer paths; `machine-connection-drop.test.ts` drops the socket repeatedly across 24 Room turn flows.

- **Installed agent programs are authoritative.** Connect lists all supported harnesses and checks the selected program before probing. Runtime startup preserves missing-program install hints in Room receipts. Claude/Codex/Pi adapters receive the user program paths; adapter updates follow npm latest with a 24-hour publish-age delay, side-by-side installs and the shared session-start check before atomic adoption; optional bundled harness binaries remain omitted. The daily feedback-triage adapter check uses no login or credential. Commands, overrides and proof: [installed agent programs](agent-programs.md).

Handoff tools deliver reports, posts and orders that name private paths, with an advisory warning to the sender that recipients may not be able to open them. Upload deliverable files with `post_artifact` and cite their attachment filenames; required brief files still travel through the target brief. Tracked relative source citations remain valid. Regression: `read-only-mcp.report.test.ts`; two-agent built-service proof: `npm run prove:report-files` (`handoff-files-unreachable`).

## Lifecycle, commands and model selection

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

### ACP startup

- **Failed activation owns its harness cleanup.** Room and corner loops stop an unusable prior client before replacement, and discard the new client if cold activation fails, including after session creation. Native resume failure still falls back on the same client. The explicit ACP `-32000 Authentication required` refusal produces a terminal `not-signed-in` receipt; provider refresh races retain bounded hiccup retries. Regression and real subprocess proof: `monolith-activation-failure.test.ts`.

- **ACP scopes bind to the helper's lifetime without ordering after its readiness.** `AcpResourceScope` (`apps/body/src/acp-resource-scope.ts`) keeps `BindsTo` without `After`: the notify helper can initialize ACP before READY, so ordering its scope after readiness can deadlock startup (`acp-resource-scope.startup.test.ts`).
- **Intake precedes retention work.** `room-runtime.ts` starts Room command loops and corner subscriptions without awaiting pending legacy migration; archived cleanup runs in the background and preserves unpublished work. Repository repair runs on the first fetch of an active cache, without scanning archived object stores at startup (`room-runtime.startup.test.ts`, `workloop-watchdog.test.ts`, `repository-cache-repair.test.ts`).
- **Native conversation memory survives helper restarts.** Codex/Grok Room and corner loops load the matching harness session and its delivered row IDs from private `agent-home/warm-transcript.json`. Configuration/checkout changes, failed native loads and the unchanged 30-minute idle boundary start cold; unsupported harnesses retain bounded transcript replay. Open Room storage preserves the resume record; archive removes it with the private home (`monolith-native-resume.test.ts`, `warm-transcript.test.ts`, `storage-bloat.regression.test.ts`).
- **Fixed context blocks are session scoped on verified harnesses.** Codex and Claude adapters use guarded instruction/compaction support; Pi checks its compaction journal before assembly. Changed blocks, cache misses, native loads, failed delivery, compaction and adapter restart restore context. The workspace-core task-start action remains per-turn. Version guards, two-model replay and native shell cap proofs: [token budget proof](agent-token-budget-proof.md); original Codex measurements: [Codex prompt delivery](codex-prompt-delivery.md).

### Tagged control commands

- **An exact tagged lifecycle command is server control, never a model prompt.** `routeHumanMessage` treats a whole message `@agent restart|status|stop|retry|debug|help|login` (or `@agent /restart`, `/login`) as control. Status/help follow access policy; restart, stop, retry and debug are open to anyone in the Room (debug reports only this Room's turn); login is owner-only. Restarts coalesce per agent in `agent_commands` until `ConnectionPresence` sees a new lifecycle id.

### Model catalog

- **A model picker is a live account verdict.** `apps/body/src/model-catalog.ts` offers only models proved through the startup-validation setter; the phone renders `agents.model_catalog` + `selected_*` verbatim (`model-catalog-sync.ts`). A failing persisted selection becomes `agents.model_unavailable` and the `wrong-model` silence line. Transient 429/529/timeout/auth-shaped failures are hiccups, never a model verdict (`isTransientProviderText`, `isAuthShapedFault`); a vanished id falls back within its family (`resolveModelFamilyFallback`).

- **Agent tool schemas stay compact.** `minimal-tool-surface.ts` declares the canonical ordinary tools; `read-only-mcp.ts` validates advertised schemas and maps only those tools to authorized internal operations; legacy names and input aliases are refused. Workflow, wallet, browser-share and avatar schemas are discovered through `app_tool` first-party routes; no mid-session tool-list refresh is assumed. `room-session.ts` mounts repository/scratch fallbacks only when native IO is unproven, and Claude alone needs the explicit silent receipt. An offline Codex Room keeps scratch IO even with a native shell (`roomNativeIoProven` in `harness-capabilities.ts`). `revise_corner(action:brief)` accepts a complete brief projection copied from `read`; Body discards returned metadata and the server resolves approval and files again. Schedule updates/deletes still require a turn started by a human Workspace admin of the schedule’s Room; scheduled wakes are refused. Schedule prompts are bounded to 2,000 UTF-16 code units and report text to 16,000. Proof: `node --import tsx scripts/prove-tool-description-contract.mjs` after building Body and server (R1/R2). Measure exact descriptors with `npm run measure:agent-tools -- <output-dir>`; authority and privacy regressions live in `minimal-tool-surface.test.ts`, `commander.integration.test.ts` and `corner-lifecycle.test.ts`.

Reviewer prompt targets use one live `getPrChecksStatus` read per wake, plus the current brief and local git head. A stored pending lifecycle cannot override live passing checks; a mismatched checkout or unavailable provider read gives an unverified-target instruction, never a claim that GitHub checks failed. Coverage: `monolith-corner-turn.test.ts`, Reproduction `stale-green`.

## Turn ownership protocol rollout

`BEELINE_NETWORK_ROUTER_V1` defaults on for every deployment; explicit `0` retains the rollback setting shared by phone projections, helper activation, overlays, usage, turn ownership and MCP member delivery. Production composition is in `apps/server/src/network-router-runtime.ts` and `index.ts`. Each protocol still requires its matching negotiated capability. A selected claim binds its command and generation to the actual registered connection ID and epoch. The existing aggregate server lease is the only renewal; it never refreshes `agent_turns.created_at`, command timestamps, or a user-state journal. Genuine start/progress/terminal transitions still persist. Initial state and actual connection replacement, release, listener recovery or server-lease expiry drive owner loss through the pending-command hand-back. No per-turn expiry scan or retry timer is added.

The machine socket carries ordinary requests and source-bound claim, receipt and stop acknowledgement controls through the same request owner. A connection loss leaves pending requests waiting. The successor registration re-reads sent request IDs and subscribes to current Room commands. A changed authenticated owner stops its previous owned task once; a re-claimed command receives a fresh generation. A generation never rebinds to another source. Harnesses and MCP launch environments bind to their generation-specific command context path (`session-command-binding.test.ts`, `helper-turn-channel.test.ts`, `machine-link-recovery.test.ts`).

A failed receipt that committed a requeue can confirm its exact old outcome while the command is pending with generation, source and lease cleared, its old failed turn and immutable source binding still agree, and current access/registration remain valid. This is read-only receipt confirmation, never a new claim. Any new claimed generation, foreign source or expired lease refuses it (`turn-ownership-terminal-receipt.test.ts`).

Nullable source columns preserve old rows. All runtime active/expired command readers use the same effective-owner predicate, including counts, workflow recovery, command queues and tool authorization. The schema and owned-row meaning must remain on server rollback even if admission is disabled; an older server that ignores source ownership is below that protocol floor. This does not impose a new native binary minimum.

An actual owned database effect holds the existing authority writer fence and rechecks current Room/Workspace access inside its transaction before source and command locks; owned replies use that transaction rather than the legacy atomic shortcut. Claim, stop acknowledgement and background completion use the same order. Each actual effect registers one ephemeral fence per transaction and source. Its deferred commit trigger checks the immutable generation, current registration and aggregate lease again at commit, then removes the evidence. An admitted transaction whose lease expires rolls back; authorization earlier in the transaction cannot extend the lease. Final socket replies check current source time immediately before synchronous enqueue. Unsupported owned external operations refuse before entering the provider until their own authority and durable UNKNOWN adapter is proven. Legacy effects retain their explicit compatibility path. The focused two-pool authority/effect proof is `turn-ownership-authority.postgres.test.ts`.

Failed corner receipts take the existing lifecycle lock before authority, matching close and account-removal writers; ordinary activity takes no lifecycle lock. Archival writers acquire authority before command, Room, member or fact row locks, including the human/helper close and merged-PR boundaries. Account deletion discovers its corner lock set without row locks and refuses a concurrent scope expansion before erasure; another explicit deletion attempt owns fresh discovery. All daemon operations return the first transaction failure without deadlock replay; another explicit action reacquires current authority (`turn-ownership-recovery.test.ts`, `R-BRIEF-DEADLOCK` in `commander.integration.test.ts`). No provider runs under these authority locks.

- **Initial Room data follows registration without a deadline.** Correlated inbox, command and subscribed frames complete initial data once; unrelated control frames cannot certify it. Only an actual connection close replaces the transport. Unsubscribe fences old awaited reads before a new subscription can complete. Coverage: `intake-reconnect.test.ts`, `machine-link-recovery.test.ts`, `machine-connection-drop.test.ts`.

Router admission is universal by default. Protocol negotiation, current grants, source ownership and listener readiness remain correctness requirements. Free-agent model access binds the request generation/current source (`owned-model-claim-socket.test.ts`); it must not borrow another owner's current command.
