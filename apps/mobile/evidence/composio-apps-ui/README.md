# Connect an app board evidence

The `mock/` frames render the four captain-approved `.dc.html` boards from `/home/lunchbox/firstmate2/data/composio-apps-mock`. The `app/` frames are screenshots of the running Expo web app at 390 × 844 using the in-process design-audit fixture. Fixture data is synthetic: Tubing Crew, lunchbox, Monarch, Gmail, Calendar, and Slack. The fixture uses the real server phone operations and a fake provider response, so these frames do not prove live OAuth credentials or phone browser behavior.

Main, Connect, and App use the board's layout, Bone surface colors, Grok Mono Hull fonts, type sizes, row and card spacing, button treatment, and official app marks. The connected Gmail/Calendar/Slack examples stay ordinary app rows. The Room uses the existing product Room shell by main Firstmate approval; the pending card matches the board's inset, logo tile, copy, ink button, and card border. The mock's single storyboard includes the successful reply beneath the pending card; the real app shows the two states in separate frames because sign-in settles the card before the agent resumes. The agent supplies the optional one-sentence continuation, and the UI uses generic copy only when it is absent.

Reproduce with `AUDIT_COMPOSIO_BOARDS=1 AUDIT_COMPOSIO_STAGE=connected|pending|after` on `.verification/design-audit/fixture-server.mts` and Expo web at `http://localhost:8083`. The source HTML shim is generated by `.verification/composio-apps/render-approved-mock.mjs` only to render the approved boards without their external DC runtime. The `.html` files under `compare/` arrange the two screenshots without altering either image.

Live credential sign-in and the captain's Android phone remain a verification gate after the server and Body companion branches are deployed together. The synthetic `after` frame demonstrates the UI projection of an already settled connection and resumed agent reply; it does not claim an end-to-end live OAuth run.
