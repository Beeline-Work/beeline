# Body agent invariants

- **The helper is a monolith-only thin Room client:** `ThinDaemonCore` → `RoomRuntimeCoordinator` → `MonolithRoomTurnLoop`, every operation through `DaemonApiClient`. Room and corner loops share `agent-home.ts`, `acp.ts`, `session-scheduler.ts`, model selection, persona delivery, bwrap spawning, and the agent MCP (`read-only-mcp.ts`).
- **One helper process per machine, one heartbeat-checked socket.** `beeline daemon --machine` (`machine-helper.ts`) hosts every agent in-process (`agent-runtime.ts`); an agent crash retries only that agent indefinitely (5 s doubling to 60 s); auth/configuration and other permanent 4xx startup refusals retain the error until a real revision or explicit start. The machine has only starting/serving/stopping states; its native supervisor restarts every exit unless explicitly stopped. The existing local watchdog tick asks every `ThinDaemonCore` to acknowledge work-loop progress before sending `WATCHDOG=1`; status and socket traffic never feed it (`workloop-watchdog.test.ts`, opt-in `workloop-watchdog.systemd.test.ts`). Non-retryable registration and socket-upgrade refusals park for the channel/link lifetime; archived-cleanup refusals persist across helper starts, preserve local code and branches, and reclaim only ignored generated output (`machine-link.refusal.test.ts`, `live-link.test.ts`, `corner-branch-sync.test.ts`). Established agents stay serving regardless of health prose; discovered surfaces without an observed fault do not imply degradation (`machine-helper.test.ts`, `surface-health.test.ts`). Heartbeats stop on permanent 4xx refusals (`turn-receipt-heartbeat.test.ts`). Helpers learn of work only through the socket (`no-polling.test.ts`): server pings every 30 s, the helper drops a socket silent for 75 s.
- **Tool refusals are MCP `isError` results** logged via `tool-call-failure.ts`. Corner names (≤3 words) and objectives (≤24 words) are owned by `packages/api-contract/src/corner-text.ts`. Merge approval is head-bound (`corner_merge_approvals`: PR number + head SHA), never brief-revision-bound.
- **Top-level Rooms: read-only filesystem, unrestricted tools.** bwrap enforces the filesystem rule, not harness mode; `roomPermissionDecision` approves non-host MCP calls and shell (`harness-capabilities.ts`). `ensureBwrapSandbox` remembers a failed install for 24 h. Permission decisions read tool identity, never wrapper shape (`read-only-policy.ts`).
- **Workspace assets, Room harness state.** `workspace-assets.ts` selects one machine + Workspace cache/AVD-metadata tree for every harness; pinning an ACP adapter and nested CLI is optional, and failure uses the host adapter with the shared cache. `BEELINE_SHARED_ASSETS_ENABLED=0` uses the legacy layout for new turns. The Android SDK stays at its operator installation. `agent-home.ts` keeps each agent/Room's `HOME`, sign-in, config, sessions and plugin data at the existing path. Pending approvals remain server scoped by agent and Room. Codex's downloaded `cache` and `plugins/cache`, and Cargo `registry` are exact shared binds; Beeline adds no shared pip or Gradle override. Inherited toolchain settings pass through unchanged. `bwrap-sandbox.ts` masks the stable Workspaces and agents parents, then restores this Workspace's assets, this Room's home/cwd and only its required control file. The old `siblingAgentMaskPaths` remains for legacy private-layout turns. `credentialMaskPaths` still hides known operator credentials. Agents share one Unix account, so bwrap shapes ordinary path visibility and is not a security perimeter. A Room has private `/tmp`; keep rig runtimes under `$HOME`. `shared-asset-capacity.ts` applies a best-effort free-space floor and monitored private recovery reserve; private writes can race the monitor. Operator-only old-cache cleanup is in `startup-cleanup.ts`; its explicit apply command requires the helper to be stopped.
- **An agent can ask to isolate one shared cache category.** `request_shared_asset_isolation` in `read-only-mcp.ts` creates a pending `shared_asset` Agent Grant with a reason and Room card. Only a Workspace owner/admin or the agent's owner may approve or deny it; approval is standing, and the human grant ledger can revoke it. `workspace-assets.ts` selects the agent-private cache tree and `bwrap-sandbox.ts` applies exact binds from the next session; `session-config-fingerprint.ts` replaces a retained session after a decision or revocation. Categories are pinned in `agent-grants.ts`, never file paths.
- **Each repository corner gets one exact-repository GitHub App token** (`getRoomGitHubToken`); `room-runtime.ts` installs a worktree-only credential helper and the corner loop injects `GH_TOKEN`/`GITHUB_TOKEN`.
- **Corner working copies are disposable only after their work is durable.** `removeCornerWorktreeAndBranches` refuses tracked/untracked changes or a HEAD no `origin/*` ref contains. Corners share npm/pnpm caches and `CARGO_TARGET_DIR`; `warm-node-modules.ts` hardlinks a lockfile-keyed `node_modules`. Permanent archive refusals are recorded before optional preservation; `corner-disk-recovery.ts` serializes recovery across hosted agents, and `room-runtime.ts` yields reconciliation progress to the watchdog (`workloop-watchdog.test.ts`).
- **Imported MCP servers are `local` or `host`** (`mcp-route-class.ts`). A host server (Squire, or `beeline_route = "host"`) mounts only through an owner-approved `kind=mcp` route grant (`host-mcp-route.ts`). Squire uses one `SquireTaskRelay` connection per task (15-min idle lease) through the host broker.
- **Live Squire shares span model turns.** `squire-share-renewals.ts` renews `operate_share` on the session's owning connection and updates only matching live rows through `refreshComputerSession`; it does not extend the relay's idle lease. `computer-session.ts` treats an old upstream deadline as a liveness check, and consumes main-frame `navigation` notifications while the human controls the browser. Requires Squire 1.1.33. Coverage: `squire-share-renewals.test.ts`, `squire-task-relay.test.ts`, `computer-session.test.ts`.
- **Attachments reach the harness as content, never a URL** (`attachment-delivery.ts`): images go inline only when the harness (`promptCapabilities.image`) and the model (`openrouter-routing.ts` pins `input_modalities`) accept them. Only the message being answered is pre-downloaded; other transcript messages show `📎 name (type, size) id=<media id>` markers (`attachmentMarkerLines`) and `download_attachment` (`read-only-mcp.ts`) fetches one on request under `getRoomMessage` authority, sha256-deduped, with typed `not_found`/`forbidden`/`too_large`/`download_failed` refusals.
- **`post_artifact` path roots** are the checkout plus the agent's whole writable session home (`BEELINE_ATTACH_SCRATCH_ROOT`), checked by `resolveAttachPath`; `write_scratch_file` writes only there. `helper-storage.ts` replaces the private scratch TTL sweeps: confirmed archive immediately removes whole private Room folders (local conversations included; server messages retain the transcript). Open surfaces preserve credentials, settings, browser profiles and harness conversation/resume state. Other whole objects qualify only when every descendant's newest atime/mtime is at least seven days old. Scheduler leases fence Room and machine cleanup; processes, open files, mounts and emulator leases defer it. `storage-owners.ts` removes ended agents and the last local Workspace's assets, persists deferred cleanup authority, and identifies legacy checkout owners by the Room/remote/branch hash. Shared checkouts retain publication guards. Trusty Squire paths are hard-excluded everywhere. Linux inventory uses `/usr/bin/python3` with `O_NOATIME` and never follows symlinks; unavailable process/filesystem evidence fails closed. `beeline storage --dry-run` / `--orphans` and `npm run dry-run:helper-storage` make only authenticated reads and inventory, without helper lifecycle actions or credential write-back. Unknown lifecycle is reported separately from confirmed orphans. Coverage: `helper-storage.test.ts`, `storage-lifecycle.integration.test.ts`, `room-runtime.archive-cleanup.test.ts`.
- **Harness quirks.** pi ignores `session/new` `mcpServers`, so `pi-mcp-bridge.ts` writes an extension before spawn. `piHasNativeMcp` must probe with the session's own `agentEnv` (`PATH` above all), never this daemon's `process.env` — pi-acp resolves its own `pi` child against the former, and the two can name different installed Pi versions. pi-acp also relays a Pi extension's `ui.notify()` (e.g. the bundled `mcp` extension's "servers need attention" warning) as an `agent_message_chunk` tagged `_meta.piAcp.notify`; `acp.ts`'s `agentMessageChunkText` must keep treating that as non-text so a harness infrastructure notice can never stand in as the agent's reply. Cursor speaks ACP through `cursor-acp-bridge.ts` (never `cursor-agent-acp`); its login is `~/.config/cursor/auth.json`, linked by `agent-home.ts`; the helper unit PATH includes `%h/.local/bin`. claude-agent-acp `settings` must be an object (`harness-tool-scope.ts`). `meaningfulHarnessStderr` filters pi's harmless `-32601` dump.
- **Android emulator leases are per instance.** In the shared layout, `workspace-assets.ts` publishes read-only AVD metadata and agents use the operator's installed SDK; `android-emulator-lease.ts` gives each `beeline emulator -avd <name>` invocation unique writable userdata and a leased console/adb port pair in the installed emulator's 5554–5584 range. The legacy private layout still uses `android-agent-env.ts`. Agents share the uid and network, so explicit adb connections can still reach another emulator.
- **Empty turns are routing failures unless a delivering tool completed.** `MonolithRoomTurnLoop.explainEmpty` accepts a completed `report`, `order` or `open_corner` as the answer without chat prose; failed or unfinished calls still owe an answer (`monolith-room-turn.failure.test.ts`, `corner-settle.integration.test.ts`). `pi-turn-record.ts`/`empty-turn.ts` recover text or name the failure; both loops rotate the OpenRouter pin once and retry. `openrouter-routing.ts` qualifies tools/full-context/95%-uptime providers with the text probe and keeps the cheapest three by measured seven-day effective input cost, fixed for 24 h. Normal pins omit `provider.order`; pi's verified session ID enables cache stickiness. `openrouter-history.ts` owns read-only generation facts. Coverage: `openrouter-routing.test.ts`, `openrouter-history.test.ts`, `agent-home.test.ts`; [measurement and release proof](openrouter-cache-routing.md). Never set `require_parameters: true`.
- **Claimed turns have a bounded harness idle window.** `acp.ts` re-arms its 45-minute backstop on session traffic, including tool progress; open tools cannot disable it. Both turn loops discard a hung session. `turn-silence.ts` / `turn-silence-notice.ts` retry a `turn_backstop` once, then end with the failure line, including agent-triggered work. Coverage: `acp-liveness.test.ts`, `monolith-room-turn.failure.test.ts`, `turn-silence-notice.test.ts`.
- **Turn timing is daemon-side** (`turn-trace.ts`, JSONL under `<runtimeDir>/turn-traces/`), never in a Room.
- **Connect is the only onboarding flow** (`npx usebeeline connect`, `connect-command.ts`). It probes before prompting (`CONNECT_PROBE_TIMEOUT_MS`); a deferring CLI joins Rooms only in `finishAgentConnectPairing`. Edit only `packages/usebeeline/README.md`; root `README.md` is a copy made by `npm run readme:sync`.
- **`@agent /login`** (Claude Code's `/login` at the call site, every harness; `agent-sign-in.ts` server + body): writes an `agent-sign-in` card; the helper runs one of four kinds (Claude paste-back PKCE, Codex/Grok device code, Cursor approve-and-wait, Pi/Goose/OpenCode provider key) and keeps every secret; a pasted code or key crosses the server only as a NOTIFY relay, never a row, card or log; link and device code are projected to the owner only. Shape drift: `*sign-in.contract.test.ts`.
- **Connectors.** `connector-squire.ts` owns Squire install/vault/revoke; `ConnectorUsageRecorder` sends one `postConnectionUsage` per turn. Squire has no `workspace_connectors` row: its agent tool probes the local task relay when mounted and otherwise uses its machine's broker report; Connectors shows each machine's broker report (`postConnectorVault`, `squire-machine.ts`). Vault metadata belongs to its owner and machine; sign-in work remains generation-scoped in the helper queue. Coverage: `read-only-mcp.workbench.integration.test.ts`, `workbench.integration.test.ts`, `squire-machine-status.browser.test.ts`. One host `trusty-squire-broker.service` elects; every other Squire spawn is the non-electing façade (`squire-broker-link.ts`). Squire's file credential store is not masked from agents. The phone's `workbench/service.tsx` lists distinct vault references read-only and links to Squire's web vault for changes; `PhoneService.readWorkbench` omits Squire API app pointers from Apps while leaving agent routes intact. Route order is in `app-connections.ts`.

## Lifecycle, commands and model selection

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

### ACP startup

- **ACP scopes bind to the helper's lifetime without ordering after its readiness.** `AcpResourceScope` (`apps/body/src/acp-resource-scope.ts`) keeps `BindsTo` without `After`: the notify helper can initialize ACP before READY, so ordering its scope after readiness can deadlock startup (`acp-resource-scope.startup.test.ts`).

### Tagged control commands

- **An exact tagged lifecycle command is server control, never a model prompt.** `routeHumanMessage` treats a whole message `@agent restart|status|stop|retry|debug|help|login` (or `@agent /restart`, `/login`) as control. Status/help follow access policy; debug/restart need the agent owner or a Room manager; stop/retry also allow the requester; login is owner-only. Restarts coalesce per agent in `agent_commands` until `ConnectionPresence` sees a new lifecycle id.

### Model catalog

- **A model picker is a live account verdict.** `apps/body/src/model-catalog.ts` offers only models proved through the startup-validation setter; the phone renders `agents.model_catalog` + `selected_*` verbatim (`model-catalog-sync.ts`). A failing persisted selection becomes `agents.model_unavailable` and the `wrong-model` silence line. Transient 429/529/timeout/auth-shaped failures are hiccups, never a model verdict (`isTransientProviderText`, `isAuthShapedFault`); a vanished id falls back within its family (`resolveModelFamilyFallback`).
