# Project agent memory

Committed home for project-intrinsic agent knowledge: rule + authoritative file + coverage pointer. The named code and tests hold the detail; do not re-expand prose here. UI rules live in [DESIGN.md](DESIGN.md).

**Naming.** The product is **Beeline**; write "Beeline" in prose, docs, and UI copy. `buzz`/`Buzz` survives only as a legacy code identifier (`apps/mobile/sources/buzz/`, `components/buzz/`, `@beeline/buzz-client`, `BuzzClient`, `BuzzRigTransport`, `theme.buzz`, `BUZZY_RELAY_*`, the `buzz-dm`/`buzz-community-invite` wire tags). Quote those verbatim; never call the app Buzz or Buzzy. Wire tags must not be renamed.

## Core invariants (read first)

- **A bad read fails alone, and a bad release contains itself.** `apps/server/src/database.ts` keeps bounded app/enrichment/health pools apart from long-running migration pools; `PhoneService` projects core Room data before degradable enrichment; boot asserts only `beeline_schema_state` (written last by migration). `.github/actions/server-leg/action.yml` canaries one of two Fly Machines for five minutes, then updates the peer or restores the previous image; `server-rollback.yml` is manual recovery.
- **The merge gate is PR/head-scoped and GitHub-authoritative.** `GitHubOperations.prChecksStatus` reads the live PR head's GraphQL `statusCheckRollup`; webhooks only trigger re-reads. `cornerMergeGate` (`apps/server/src/corner-lifecycle.ts`) opens only on green checks + the configured parent-member reviewer's exact-head PASS (skipped when the author is the reviewer) + worker yolo + no active hold. It is the single gate for `pr_checks_status` and the server merge. Missing reviewer state is never consent.
- **The server merges; agents stop at the pull request.** Corner agents commit, push, `gh pr create`, and print the URL. `landReadyCorners` claims the head (`claimCornerMergeAttempt`) and squash-merges it; a refusal returns the corner to `implement`. No instruction may contain `gh pr merge`. The merge webhook archives the corner and reaps its worktree.
- **Corner reviewers come only from the parent Room** (`rooms.reviewer_agent_id`/`reviewer_fallback_ids`). A non-member reviewer posts a note and never falls back to the author (`reachableReviewer`). `approveCornerMerge` (`daemon-service.ts`, refusals as `CornerVerdictRejectedError` in `corner-merge-approval.ts`) accepts only a current-head, current-brief PASS; handbacks cap at `REVIEW_HANDBACK_LIMIT`, then `ask_human`. The phone has no approve-merge control.
- **`CORNER_LIFECYCLE_CONTRACT` (`corner-lifecycle.ts`) is the one authority for corner transitions.** It is plain TypeScript, never stored as a Workspace workflow; the run page draws corner runs from it by card type. Every state change goes through `advanceCorner(db, cornerId, event)` under the run lock: it validates the edge, applies loop caps (checks failing 100 / changes requested 3 → `ask_human`), writes a `@system` card, and issues the only lifecycle wake (reviewer on green, implementer otherwise). Landing wakes no one in the parent Room; agents with follow-up work subscribe to `merged`.
- **A corner has one server-owned state vocabulary:** `working|waiting|idle|review|archived`, from `deriveCornerState` (`apps/server/src/corner-state.ts` over `packages/api-contract/src/corner-state.ts`). `waiting` needs an unexpired `corner_owed` row for a human member; triggers maintain `corner_owed` in the writer's transaction and readers use `cornerOwedLookupSql`, never a per-read `messages` scan. Clients render `CornerListItem.state` verbatim.
- **A repository corner starts from a human-approved brief, never its short objective.** Brief = Markdown spec (≤ `CORNER_BRIEF_SPEC_MAX_LENGTH`) + file manifest + one approving human message resolved server-side (`resolveCornerBriefApproval`, `corner-brief.ts`). The objective is navigation only; the approval quote wins conflicts. A no-code → code upgrade gets a `SYSTEM_IDENTITY_ID` placeholder revision 1.
- **A repo-less corner runs in `rooms/<corner>/scratch`** with no token or checkout and ends only via human `requestCornerClose`. Under a repository-backed parent its agent may call `upgrade_corner_to_code` (`UPGRADE_INTENT_RULE`, `prompt-assembly.ts`); `upgradeCornerLane` is idempotent and one-way, keeps `owner_agent_id`, and writes the first brief (`composeCornerUpgradeBrief`).
- **A corner operates as a Room: membership is the authority, the branch is the shared artifact.** Only `agent_commands` authorize a turn (`agent-command.ts`); creation wakes only the opener; `membership-join.ts` copies Room joins without resurrecting removed members. Each helper syncs to `origin/<feature_branch>` before every turn (`corner-branch-sync.ts`); a rebase conflict realigns to the remote and drops local unpushed commits, never force-pushes. `corner-wake.ts` is the sole wake predicate. `DAEMON_OPERATION_ROUTES` must stay exhaustive.
- **A human tag names a corner's implementer.** `corner_facts.worker_agent_id` (NULL = opener) is set by `routeHumanMessage`, never to the parent's reviewer or fallbacks; worker-scoped reads use `cornerImplementerSql` (`corner-worker.ts`). `owner_agent_id` stays opener, brief author, and close authority.
- **A phone closes a corner only through `PhoneService.requestCornerClose`** (current member; a human-created corner closes for its creator or a Workspace owner/admin). It stops active assignments and applies `closeCornerState` (`corner-close.ts`); never close by chat prose.
- **An exact tagged lifecycle command is server control, never a model prompt.** `routeHumanMessage` treats a whole message `@agent restart|status|stop|retry|debug|help` (or `@agent /restart`) as control. Status/help follow access policy; debug/restart need the agent owner or a Room manager; stop/retry also allow the requester. Restarts coalesce per agent in `agent_commands` until `ConnectionPresence` sees a new lifecycle id.
- **Composer commands keep two authorities separate.** `BEELINE_SLASH_COMMANDS` (`packages/buzz-client/src/slash-command.ts`) owns Beeline actions, filtered by live permissions; an agent's ACP `available_commands_update` snapshot (`agentCommandCatalogPublisher` → `agents.commands`) owns its commands. Picking one keeps the `@agent` mention, so routing and access policy still gate it. Owner-only `/fast-mode` (`fastModeCommandState`) calls `updateAgentModelSelection`.
- **Agent Grants have one vocabulary and one authority axis.** `packages/api-contract/src/agent-grants.ts` owns kinds, statuses, the command-rule parser (`parseCommandGrantTarget`; `commandGrantMatches` is an argv prefix) and the decision line; policy follows `docs/approval-matrix.md`; `surface-capabilities.ts` lets a corner dominate a Room. Yolo defaults on (`backfillYoloModeDefault`) and is forced off in public Workspaces; credential-file argv and unread scripts (>4096 B/120 lines) still stop. Human profiles show a read-only grant ledger (`readWorkspaceMembers`, `MemberGrantRow.tsx`, wording only in `grantProvenanceLine`); the agent settings page shows none.
- **Removing an agent retires it; its work survives.** `PhoneService.removeAgent` → `retireAgentFromWorkspace` (`agent-retirement.ts`) ends memberships, revokes all its daemon tokens and grants, hides the identity, clears configuration, and deletes schedules; corners, turns and messages stay. A helper retires only on 403 `agent_removed` (`isAgentRemovedError`), never on transport errors, 5xx, or plain 401.
- **`deleteWorkspace` is owner-only and a real `DELETE`** relying on FK cascades. It checks existence before ownership (idempotent retries), writes `workspace_deletions` + per-member notices, revokes tokens only for agents with no other membership, and leaves media to `media-ttl.ts`. Every FK column into `messages`/`rooms`/`workspaces` must carry a leading-column index — an unindexed one forces Postgres to sequentially scan that whole child table per deleted row during the cascade, which is slow enough on a real table to blow the app pool's `APP_STATEMENT_TIMEOUT_MS` and leave the client's delete request hanging with no answer. Guarded by the `cascade-path foreign keys stay indexed` test in `database.test.ts`; `messages` itself is busy enough that a new index there goes through `createIndexConcurrently` in `migrate()`, not inline schema SQL.
- **Leaving a Room.** Any human can leave a top-level Room (`PhoneService.leaveRoom`, under the Room row lock); the last Workspace owner/admin in it deletes it for everyone and must pass `confirmDelete: true`. `leaveDeletesRoom` drives `buzz/room-leave.ts`. Swiping a DM writes a per-viewer `chat_dismissals` row hidden only until newer inbound activity.
- **Institutional memory has two scopes and stays optional to every turn.** On by default; only an explicit `false` on `BEELINE_INSTITUTIONAL_MEMORY_ENABLED`/`_SHADOW_ENABLED` disables it. No background review: the answering agent maintains it with `search_memory`/`save_memory`/`update_memory`/`delete_memory`/`report_memory_used` (versioned, active-command-bound). Snapshot and search are hybrid (word overlap + vector recall over memory items and `workspace_skills`). Each turn's snapshot is capped at `INSTITUTIONAL_CONTEXT_HARD_MAX_BYTES` (1 KB) and fetched alongside harness activation (`institutional-context.ts`); a miss says so. Only agent-saved Workspace facts expire (`institutional-curator.ts`, default 90 days). Procedures are staled by their code anchor's blob changing (`institutional-skill-anchors.ts`, fail-open). Contracts: `packages/api-contract/src/institutional-memory.ts`.
- **A workflow is a `workspace_skills` row with `kind='workflow'`, with no run-state tables.** `readWorkflowContract` (`packages/api-contract/src/workflow-contracts.ts`) validates it; `apps/server/src/workflow-runs.ts` is the whole runtime. The start card's id is the run id, state is the latest `workflow-handoff` card, wakes go through `systemLine`, saves use `applySkillRevision`. A wake names its run (`workflowWakeDetail`, `agent-command.ts`: continue this run, do not start a new one), and `startWorkflow` refuses a second active run from the same schedule occurrence (`activeRunForTrigger`). Roles and corner reviewers may be ordered agent lists; `agent-health.ts` picks the first healthy current member, and `noteFirstSilence` fails over. Proof: `npm run prove:workflow-run`.
- **Beeline feedback has one store and one sweep.** Agents file friction with `report_feedback` (10/agent/UTC day, 24h dedupe, never fails the turn); people use a bare `@system` tag or Report issue. Store/notify: `apps/server/src/feedback.ts`. Triage is the seeded `feedback-triage` workflow (`docs/workflows/feedback-triage.json`). The only closing write is `notify_feedback_fixed`, which needs a merged PR in `BEELINE_FEEDBACK_REPOSITORY`.
- **The GitHub star card stars only on the person's own tap and never gates anything** (`github-star-prompt.ts`, `StarPromptCard.tsx`; due at the 3rd/30th/300th agent reply, held mid-conversation or after a failure).
- **Corner Apps are installed data, never downloaded code.** `packages/api-contract/src/corner-apps.ts` owns the vocabulary and v1 permission manifest; `corner_app_installations` is the Workspace library; `corner_app_bindings` binds at most one app per corner via the manual `+` flow.
- **An agent's animal is its face, name and soul, assigned together by the server.** `assignSeededAgentIdentity` (`packages/api-contract/src/faces.ts`) gives the first animal no current Workspace member wears, else `defaultFaceForSeed` + a roman numeral, inside `PhoneService.claimAgentConnectPairing` under `workspaces … FOR UPDATE`. `confirmSeededName` offers a rename for 15 minutes. Face ids are pinned in two copies (`faces.ts`, `apps/mobile/sources/buzz/faces/index.ts`) so no screen needs a fresh SDK `dist/`. Handles: `availableAgentHandle`; human handles win collisions (`workspace-handles.ts`).
- **A model picker is a live account verdict.** `apps/body/src/model-catalog.ts` offers only models proved through the startup-validation setter; the phone renders `agents.model_catalog` + `selected_*` verbatim (`model-catalog-sync.ts`). A failing persisted selection becomes `agents.model_unavailable` and the `wrong-model` silence line. Transient 429/529/timeout/auth-shaped failures are hiccups, never a model verdict (`isTransientProviderText`, `isAuthShapedFault`); a vanished id falls back within its family (`resolveModelFamilyFallback`).
- **A non-agent system author is a hidden `kind='human'` identity** with a fixed id (`SYSTEM_IDENTITY_ID`, `REVIEW_IDENTITY_ID`, `SCHEDULE_SCHEDULER_ID`), never a new `identities.kind`. `system-line.ts` sends Workspace facts to each member's read-only `@system` DM (`assertRoomIsWritable`).
- **Deleted features stay deleted.** Chat-sentence tombstones: `isRetiredAgentNotice` (`packages/buzz-client/src/retired-agent-notices.ts`, exact set + bounded structural regexes), applied in push-gateway `projectEvent`, `room-list-row.ts`, and the mobile cache scrub. Photo overrides stay off (`PHOTO_OVERRIDES_ENABLED=false`). Repoint here; never restore the feature.
- **Dead code is baseline-gated.** After building workspace `dist/`, `npm run dead-code` runs Knip against `knip-baseline.json`; only run `dead-code:baseline` for an intentional API addition. Expo Router entries are declared in `knip.jsonc`.
- **Hand-testing `beeline start`/`pair` in a worktree can start a REAL production daemon** (runtime pointers live in the shared git common dir; `start-command.ts` converges the machine helper). Always set an isolated `XDG_STATE_HOME`, and `--repo` a throwaway repo for `pair`.

## Relay and client protocol

- **kind:30078 reads filter by `#d`, never `#h`** (a `#h` filter matches nothing). `agentPresenceKey` (`packages/buzz-client/src/agent-presence.ts`) builds presence keys. Test with `matchesFilterRelayFaithfully`/`deliverRelayFaithfully` (`client.test.ts`); generic stubs miss this.
- **Production relays may answer a multi-value `#h`/`#d` filter for one key only**, so every `packages/buzz-client` fan-out sends one single-key filter per key inside one batched query.
- **Local stack vs production.** `relay-stack/compose.yml` (http `127.0.0.1:3010`, the `relay-config.ts` default) has a credential-free materializer and cannot serve GitHub-backed corners (`githubHttpsRemote` maps `git://` remotes to GitHub HTTPS), so pair repo-less Rooms there. `BuzzClient` treats loopback/`10.0.2.2` relays as open. `@beeline/gate` reads `BUZZY_RELAY_*` at import. Gate live tests: `npm run stack:up`, then `cd apps/gate && npm run test:live`.
- **The phone has one write transport:** the authenticated monolith API. `BuzzRigTransport` is an alias of `MonolithRigTransport`; the `@beeline/buzz-client` HTTP bridge and `apps/gate` serve only the isolated relay stack and scripts.
- **Community model.** `community.ts` maps NIP-29 (kind:9007 self-referencing `community=<h>`, 9000 roles, 39001/39002). Room tenancy is the server-stamped `channels.community_id`. Workspace membership means membership in every live top-level Room. Invites are signed kind:30078; DMs are deterministic Rooms; in a two-member agent DM every human message addresses that agent (`routeHumanMessage`). `invite-only` maps to NIP-29 `private`; outsiders redeem a pairing marker through `/agent-pairing/claim` (`apps/push-gateway/src/server.ts`); proof: `npm run prove:private-pairing`.
- **Key succession.** Roles resolve at the roster funnel (`communityMembers(…, {predecessors})` → `inheritRolesThroughSuccession`); the ledger is `beeline_key_successions` (`apps/auth/src/store.ts`).
- **App links** live in `relay-stack/web/.well-known/` (paths/packages: `scripts/app-associations.mjs`; drift: `app-association-drift.yml`). Store review uses `beeline://review/<secret>`; the HTTPS form is a fallback.

## Server-indexed surfaces and Room reads

- **Server-indexed surfaces are the only durable read authority.** `apps/push-gateway/src/room-indexer.ts` owns paint-ready queries; `packages/buzz-client/src/room-view.ts` owns DTOs + the signed client. Screens render validated responses as-is; a relay signal only marks a surface dirty. Never restore client reducers or snapshots.
- **A Room GET does not carry child corners.** `PhoneService.readRoom`/`RoomView` stop at the Room; corners come from `RoomViewClient.corners`, and the chat list's `cornerCount`/`openCorners` feeds `DesktopRoomCorners`. Opening a Room makes one live subscription (`useRoomSurfaceSession`); never expand watch-filter keys into per-corner subscribes.
- **A Room payload is projected, never all-or-nothing.** `readRoomView` (`phone-guards.ts`) fails only on a missing `room.id` or `messages`; unreadable optional fields are absent, never invented; unknown `role` reads `member`; `repositoryResolution` reads `unverified`.
- **Turn progress is server receipts only** (`RoomView.latestAgentTurns`; fresh `working` until terminal state or 90 s), never drafts or presence. Room `agentState` is the max of its own and its open corners' (`CHAT_LIST_SQL`). Stop is allowed for the requester or a Room owner/admin (`cancelAgentTurn`) and shown only by `TurnProgressLine.tsx`.
- **Drafts.** Top-level Room `postAgentDraft` is a successful no-op (C109, `DaemonService.liveOutput`); corners store and publish drafts. Draft rows key on agent + request (`draft-settle.ts` `liveDraftRowId`), anchored at the turn's first snapshot. `LiveHub` reaches only listening sockets, so `PhoneService.liveDraftSnapshot` hands a late subscriber the current draft once. `turn-stream.ts` (`AgentTurnStream`) owns the bounded draft lane and one durable reply; corners also keep narration.
- **An ordinary final reply commits in one statement.** `DaemonService.postRoomMessage`'s no-mention path does authority, attachments, turn settlement, insert, command completion, draft cleanup and offline-notice withdrawal in one CTE (`daemon-service.completion-latency.test.ts`). Agent-to-agent hops count from `triggerMessageId`; the third hop persists without a delivery mention.
- **Server commands are the only helper work authority.** `agent-command.ts` stores `input`/`resume`/`stop`; `server-command-intake.ts` claims them; agent tags in a committed reply dispatch in the same statement up to depth 3. Conversation windows (`RoomConversationInput.window`, `warm-transcript.ts`) are context, never authority.
- **Silence and failure.** `noteFirstSilence` (`turn-silence-notice.ts`) owns silence/failure episodes, phrased by `packages/api-contract/src/turn-silence.ts`. Hiccups reopen the command (≤3 attempts, one give-up line); standing conditions complete it; transient corner-start failures stay pending.
- **Mentions are read, never stored.** `message-mentions.ts` (`resolveCurrentMemberMentions`, SQL twin `taggedIdentityIdsSql`) matches exact current handles against current Room membership. `agent-access.ts` alone decides who may address an agent; `noteUnansweredMentions` writes one line per reason (not a member, policy, offline after 90 s via `pending_mention_notices`). At most one push per recipient per agent turn (`background.ts`).
- **Live fanout crosses machines through PostgreSQL.** `postgres-live.ts` owns id-only triggers and a session `LISTEN` (`DATABASE_LISTENER_URL` when the main URL is pooled). The phone holds one `LiveConnection` that paints committed rows, then reconciles; the 30 s invalidation is a recovery net.
- **Mobile storage and reads.** `surface-storage.ts` persists only response + outbox partitions; cold open installs invalidation, then one signed GET. Read marks are server-owned (`room_read_marks`; `RoomView.viewer.readCursor`). `buildReplyCommand` (`reply-command.ts`) alone writes `h`/`e` tags; `relay-error.ts` alone interprets publish refusals.
- **The Needs-you tray is a server projection** (`apps/server/src/needs-you.ts`): a cell is a message that tags the viewer and asks (ends `?` or says please/approve/feedback), or a decidable grant card. Cells leave on tap/dismiss, a later viewer message, a decision, or 24 h after first paint.
- **Presence recovery bounds candidates before resolving tags** (`ConnectionPresence.observe`, `PushDeliveryLoop.runOnce`); inlining the tag matcher exhausted production pools in v0.0.95.
- **Room joins go through `membership-join.ts`.** Sign-in and `migrate()` create no membership; a person with no Workspace lands on create-or-join. `createWorkspace` makes a public `#general` (`first-room.ts`). An explicit join writes one `member-joined` note; a Workspace arrival writes one `@system` DM line per human.
- **First-entry welcome is four modal cards** (`components/buzz/WelcomeCards.tsx`, human viewers only), driven by `identities.welcome_cards_due` via `readWelcomeCards`/`completeWelcomeCards`.
- **Repository workflows** are dispatched only by human Workspace managers (`listRoomWorkflows`/`dispatchRoomWorkflow`, exact-repo token, stored default branch).
- **Reviewer sign-in.** `apps/server/src/review-access.ts` owns the store reviewer identity and `BEELINE_REVIEW_SECRET` (constant-time compare, rate limited, misses 404); entry is only the `/review/` link.

## System lines and events

- **One producer, one grammar.** `apps/server/src/system-line.ts` produces every `system`/`card` line as `<subject> <verb>[ <object>][ · <consequence>]` (past tense, `@handle` names, no colon/em dash/trailing period; `system-line.contract.test.ts`). The phone folds same-verb runs (`buzz/system-lines.ts`) and renders with `LedgerSystemLine`.
- **A line's `kind` is the contract; its `verb` is prose.** `packages/api-contract/src/system-events.ts` owns `SERVER_EVENT_KINDS`/`RESUME_KINDS`/`CONTROL_KINDS`/`MAX_*`. Subscriptions live on Room membership (`memberships.event_subscriptions`); `systemLine()` resolves `mentions ∪ subscribers`, and `routeSystemCommand` turns a kinded line into input/resume/stop with no sender access check.
- **An agent subscribes and emits for itself; the server owns the cause.** `subscribe_events`/`emit_event` touch only the caller's membership; `systemLine` derives cause/root/depth under an advisory lock and refuses past `MAX_EVENT_DEPTH`/`MAX_TURNS_PER_ROOT`. Caused lines sort at `GREATEST(now(), cause+1s)`.

## Branch conventions and CI

- `fm/*` branches stack: check `gh pr list --json baseRefName,headRefName` before assuming a file is on `main`. A stack merged base-first does not propagate; re-target to `main` and verify with `git grep <symbol> origin/main`.
- A cherry-pick off `feature/*` can drop a context-only declaration; root `npm run typecheck` catches it. Never stage the git-ignored `relay-stack/web/dl/` bundles.
- Resolve merges as one batch: list every textual conflict and semantic overlap, resolve them in one pass, then run one integration matrix.
- **`TYPECHECK` (root `npm run typecheck` = turbo + `apps/mobile` + `tsconfig.scripts.json`) and `SHARED PACKAGE TESTS` run on every PR.** Two green PRs can still merge into a red `main`; after changing a shared row type, merge `origin/main` and re-run typecheck.
- **In `checks.yml` a job `name:` is a required check context.** Never rename one; skip only with a job-level `if:`; every gate must execute something. Heavy suites filter by module path; `packages/**` runs everything. `npm run lint:workflow-paths` fails a workflow naming a test path nothing matches.

## Body (@beeline/body)

- **The helper is a monolith-only thin Room client:** `ThinDaemonCore` → `RoomRuntimeCoordinator` → `MonolithRoomTurnLoop`, every operation through `DaemonApiClient`. Room and corner loops share `agent-home.ts`, `acp.ts`, `session-scheduler.ts`, model selection, persona delivery, bwrap spawning, and the agent MCP (`read-only-mcp.ts`).
- **One helper process per machine, one heartbeat-checked socket.** `beeline daemon --machine` (`machine-helper.ts`) hosts every agent in-process (`agent-runtime.ts`); an agent crash restarts only that agent (5 s doubling to 60 s). Helpers learn of work only through the socket (`no-polling.test.ts`): server pings every 30 s, the helper drops a socket silent for 75 s.
- **Tool refusals are MCP `isError` results** logged via `tool-call-failure.ts`. Corner names (≤3 words) and objectives (≤24 words) are owned by `packages/api-contract/src/corner-text.ts`. Merge approval is revision-bound (`corner_merge_approvals`: PR number + head SHA).
- **Top-level Rooms: read-only filesystem, unrestricted tools.** bwrap enforces the filesystem rule, not harness mode; `roomPermissionDecision` approves non-host MCP calls and shell (`harness-capabilities.ts`). `ensureBwrapSandbox` remembers a failed install for 24 h. Permission decisions read tool identity, never wrapper shape (`read-only-policy.ts`).
- **Agents share one Unix account, so bwrap isolates them.** `siblingAgentMaskPaths` + `credentialMaskPaths` are merged at every `maskPaths:` site; file modes are defense-in-depth only. `~/.gnupg`, `~/.config/gcloud`, `~/.docker`, `~/.npmrc` remain unmasked (`bwrap-sandbox.ts` docblock). bwrap gives each harness a private `/tmp`, so keep rig runtimes under `$HOME`.
- **Each repository corner gets one exact-repository GitHub App token** (`getRoomGitHubToken`); `room-runtime.ts` installs a worktree-only credential helper and the corner loop injects `GH_TOKEN`/`GITHUB_TOKEN`.
- **Corner working copies are disposable only after their work is durable.** `removeCornerWorktreeAndBranches` refuses tracked/untracked changes or a HEAD no `origin/*` ref contains. Corners share npm/pnpm caches and `CARGO_TARGET_DIR`; `warm-node-modules.ts` hardlinks a lockfile-keyed `node_modules`.
- **Imported MCP servers are `local` or `host`** (`mcp-route-class.ts`). A host server (Squire, or `beeline_route = "host"`) mounts only through an owner-approved `kind=mcp` route grant (`host-mcp-route.ts`). Squire uses one `SquireTaskRelay` connection per task (15-min idle lease) through the host broker.
- **Attachments reach the harness as content, never a URL** (`attachment-delivery.ts`): images go inline only when the harness (`promptCapabilities.image`) and the model (`openrouter-routing.ts` pins `input_modalities`) accept them. Only the message being answered is pre-downloaded; other transcript messages show `📎 name (type, size) id=<media id>` markers (`attachmentMarkerLines`) and `download_attachment` (`read-only-mcp.ts`) fetches one on request under `getRoomMessage` authority, sha256-deduped, with typed `not_found`/`forbidden`/`too_large`/`download_failed` refusals.
- **`post_artifact` path roots** are the checkout plus the agent's whole writable session home (`BEELINE_ATTACH_SCRATCH_ROOT`), checked by `resolveAttachPath`; `write_scratch_file` writes only there. `scratch-sweep.ts` (run by `agent-runtime.ts` every 6 h) deletes files older than `BEELINE_SCRATCH_TTL_HOURS` (72) and skips harness state dirs by name.
- **Harness quirks.** pi ignores `session/new` `mcpServers`, so `pi-mcp-bridge.ts` writes an extension before spawn. Cursor speaks ACP through `cursor-acp-bridge.ts` (never `cursor-agent-acp`); its login is `~/.config/cursor/auth.json`, linked by `agent-home.ts`; the helper unit PATH includes `%h/.local/bin`. claude-agent-acp `settings` must be an object (`harness-tool-scope.ts`). `meaningfulHarnessStderr` filters pi's harmless `-32601` dump.
- **Empty turns are routing failures.** `pi-turn-record.ts`/`empty-turn.ts` turn every empty turn into recovered text or a named reason; both loops rotate the OpenRouter pin once and retry. `openrouter-routing.ts` filters providers by tools + uptime ≥98% (24 h cache) then live-probes; never set `require_parameters: true`.
- **Turn timing is daemon-side** (`turn-trace.ts`, JSONL under `<runtimeDir>/turn-traces/`), never in a Room.
- **Connect is the only onboarding flow** (`npx usebeeline connect`, `connect-command.ts`). It probes before prompting (`CONNECT_PROBE_TIMEOUT_MS`); a deferring CLI joins Rooms only in `finishAgentConnectPairing`. Edit only `packages/usebeeline/README.md`; root `README.md` is a copy made by `npm run readme:sync`.
- **Connectors.** `connector-squire.ts` owns Squire install/vault/revoke; `ConnectorUsageRecorder` sends one `postConnectionUsage` per turn. One host `trusty-squire-broker.service` elects; every other Squire spawn is the non-electing façade (`squire-broker-link.ts`). Squire's file credential store is not masked from agents.

## Daemon self-update and CLI bundle
