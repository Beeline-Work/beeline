# System lines and event invariants

Paths and commands below are relative to the repository root. Read these invariants before editing this area; named code and tests hold implementation detail.

## System lines and events

- **Disclosure rows have no top edge.** Steps and grouped GitHub events retain a 44 px minimum tap height. `LedgerDisclosure` owns steps and non-repository-only event runs; `NotificationLifecycleCard` owns the repository-only group header. Expanded step rules and standalone repository-record rules remain.

- **One producer, one grammar.** `apps/server/src/system-line.ts` produces every `system`/`card` line as `<subject> <verb>[ <object>][ · <consequence>]` (past tense, `@handle` names, no colon/em dash/trailing period; `system-line.contract.test.ts`). The phone renders each system message separately with `LedgerSystemLine` (`buzz/system-lines.ts`), using two-line previews and brass More/Less only for measured overflow (`Ledger.test.ts`, `system-lines.browser.test.ts`); agent tool runs fold together. Consecutive repository notifications and passive wallet records fold into collapsed event runs (`buzz/pr-lifecycle.ts`, `PrLifecycleCard.tsx`): repository-only groups use their own header; other groups use `LedgerDisclosure`. Expansion retains one line per committed event. Corner lifecycle facts anchor `CornerOpenedMarkers` beneath the requesting message in a Room, DM or corner: gold branch glyph, Opened/Merged/Closed, bare name, and a linked PR number only on Merged. Merge and close update the existing cards in the same transaction, invalidating their source transcripts. Source-free opening records remain subscription events but are omitted from phone reads. Only off-Room requests get a new Room Merged card; Room call sites already show the merge. Private orders/reports have no transcript marker; automatic wakes never borrow a historical root message. Cleanup stays silent. Human/agent messages and actionable cards end the run; check history retains its posted state while the corner header owns live state. Coverage: `corner-callsite.integration.test.ts`, `CornerOpenedMarker.test.tsx`, `pr-accordion.test.ts`, `ci-accordion.test.ts` and their browser regressions.
- **A line's `kind` is the contract; its `verb` is prose.** `packages/api-contract/src/system-events.ts` owns `SERVER_EVENT_KINDS`/`RESUME_KINDS`/`CONTROL_KINDS`/`MAX_*`, plus one `SERVER_EVENT_KIND_DETAIL` line per kind (`eventKindCatalogLines`) — the single source `subscribe_events` and the agent rulebook both read, so a kind with no detail fails to compile rather than drift silently. `systemLine()` resolves `mentions ∪ subscribers`, and `routeSystemCommand` turns a kinded line into input/resume/stop with no sender access check. A `PER_ITEM_EVENT_KINDS` kind wakes its owner, never subscribable; `SUBSCRIBABLE_EVENT_KINDS` is.
- **Subscriptions are event-driven actions without approval.** `apps/server/src/agent-subscriptions.ts` stores a Room or covered repository event plus its prompt/optional workflow target; `systemLine()` emits one `subscription-fired` line per matching Room subscription and still reads legacy `memberships.event_subscriptions` for `subscribe_events`. Verified GitHub App deliveries emit one per matching repository subscription per delivery. `subscriptionActionPrompt` (`packages/api-contract/src/subscriptions.ts`) puts the trusted action before the quoted untrusted payload. The phone's Schedules and subscriptions page lists these with the same detail grammar and stop control. Connected Slack channel messages register a Composio webhook trigger on the existing account (`composio-apps.ts`); `/v1/connectors/events/composio` verifies the signed delivery and dedupes each subscriber wake. Linear and Stripe provider hooks run through the helper's official MCP credential and `provider-webhooks.ts` on both sides; the server verifies signatures and dedupes each subscriber wake. `list_subscription_events` advertises connected sources with a delivery path; Gmail and Squire-only connections are not offered yet.
- **An agent subscribes and emits for itself; the server owns the cause.** `subscribe_events` touches the caller's legacy membership list; `emit_event` acts only in its Room. `systemLine` derives cause/root/depth under an advisory lock and refuses past `MAX_EVENT_DEPTH`/`MAX_TURNS_PER_ROOT`. Caused lines sort at `GREATEST(now(), cause+1s)`.
- Approval cards resume paused turns through `RESUME_KINDS`, never typed human confirmation. Squire decisions arrive on the originating `SquireTaskRelay` connection, including vault operations without a browser session; never poll. Squire sends no expiry event, so the forwarder posts `expired` at `expires_at`. Coverage: `squire-task-relay.test.ts`, `squire-mcp-client.test.ts`, `integration.test.ts`.
