Keep shared safety rules here; read the area guide below before editing that subsystem. Named code and tests hold implementation detail. UI authority: [DESIGN.md](DESIGN.md).

## Shared safety and authority

- **Isolate lifecycle proofs.** Hand-testing `beeline start`/`pair` in a worktree can drive a real production daemon through shared git runtime pointers. Use isolated `HOME`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, a separate native manager, and a throwaway `--repo` for pairing. Real install/start/update proofs: `scripts/helper-proof/run-linux.sh`; guard: `lifecycle-test-guard.ts`. Details: [development guide](docs/agent-development.md).
- **Merge authority:** live GitHub checks green + a yes on the exact PR head + no hold. `GitHubOperations.landCorner` is the only merge path and requires a current repository-work brief. No agent instruction may contain `gh pr merge`; yolo never bypasses the gate. Read [corner authority and lifecycle](docs/agent-corners.md) before changing corners, review or dispatch.
- **Work authority:** only `agent_commands` authorize turns; membership authorizes Room/corner access. Orders go down and reports go one step up. Conversation history is context. Contracts: [corners](docs/agent-corners.md), [server surfaces](docs/agent-server-surfaces.md).
- **Read authority:** server-indexed DTOs own durable client state; render validated responses as-is. Live events invalidate or deliver committed deltas; never restore client reducers, snapshots or phone polling. Read [server surfaces and Room reads](docs/agent-server-surfaces.md).
- **Deleted features stay deleted.** Chat-sentence tombstones: `isRetiredAgentNotice` (`packages/buzz-client/src/retired-agent-notices.ts`, exact set + bounded structural regexes), applied in push-gateway `projectEvent`, `room-list-row.ts`, and the mobile cache scrub. Photo overrides stay off (`PHOTO_OVERRIDES_ENABLED=false`). Repoint here; never restore the feature.
- **Releases:** merging to `main` never releases. Firstmate runs the routine `gh-axi workflow run unified-release.yml --ref main` with no release worker and no inputs; overrides are recovery-only. Read [release policy and recovery](docs/release-pipeline.md) before release work. Never suggest `npx beeline`; CLI recovery is `npx usebeeline update` ([bundle runbook](docs/cli-bundle-channel.md)).

## Development and CI

- `fm/*` branches may stack; inspect live PR bases before assuming work is on `main`. Never stage ignored `relay-stack/web/dl/` bundles. Resolve all merge conflicts and semantic overlaps in one batch before validation ([development guide](docs/agent-development.md)).
- Root `npm run typecheck` includes workspaces, mobile and scripts; `TYPECHECK` and `SHARED PACKAGE TESTS` run on every PR. After a shared row-type change, integrate `origin/main` and rerun typecheck. `checks.yml` job names are required check contexts: never rename them; gates must execute something. Path checks: `npm run lint:workflow-paths`.
- Dead code is baseline-gated: `npm run dead-code` builds workspace `dist/` then checks Knip. Use `dead-code:baseline` only for an intentional API addition (`knip-baseline.json`, `knip.jsonc`).
- Edit `packages/usebeeline/README.md`; root README is generated by `npm run readme:sync` ([Body guide](docs/agent-body.md)).
