## Core invariants (read first)

- **kind:30078 reads filter by `#d`, NEVER `#h`** (a `#h` filter over kind 30078 matches nothing). `agentPresenceKey(channelId)` (`packages/buzz-client/src/agent-presence.ts`) is the one presence-key builder. Generic relay stubs cannot catch this — use `matchesFilterRelayFaithfully`/`stubRelayFaithfulPublishing` (`packages/buzz-client/src/client.test.ts`). Source assertion: `agent-presence.test.ts`.
- **Production relay may answer a multi-value `#h`/`#d` filter with matches for only one key.** Every fan-out in mobile transport and `packages/buzz-client` expands to one single-key filter per key inside ONE batched `query([...])`/subscription; fake relays answer multi-key filters first-key-only (`monolith-rig-transport.test.ts`, `client.test.ts`).
- **Local stack vs production:** `git-url.ts` maps `git://` markers to `https://`, unusable against the local docker stack (`relay-stack/compose.yml`, http 127.0.0.1:3010) — pair repo-less and invite top-level Rooms. That stack includes a credential-free materializer, so local RoomView reads stay on 3010. Mobile's `getEffectiveRelayUrl()` honors the embedded runtime URL when no device override exists, and `BuzzClient` treats loopback/Android-host relay URLs as the intentionally open local relay instead of waiting forever for a NIP-42 challenge; coverage: `buzz-identity-storage.test.ts`, `client.test.ts`. Gate helpers resolve the relay from env AT IMPORT TIME: set `BUZZY_RELAY_HOST=127.0.0.1:3010`, `BUZZY_RELAY_SCHEME=http`, `BUZZY_RELAY_URL=http://127.0.0.1:3010`, `BUZZ_RELAY_URL=ws://127.0.0.1:3010` BEFORE importing `@beeline/gate`, or reads/writes silently go to PRODUCTION.
- **Private Workspace pairing does not require a relay-wide membership gate.** `visibility='invite-only'` maps to NIP-29 `private`; an outsider redeems the globally readable kind:30078 marker through the authenticated `/agent-pairing/claim` server boundary, which atomically verifies the marker's current member author and reserves it for that exact key before the client publishes canonical kind:9000 membership. Acceptance proof: `npm run prove:private-pairing` against the ordinary open local relay.
- **Hand-testing `beeline start`/`pair` in a worktree of this repo can start a REAL production daemon** (runtime pointers live under the shared git common dir). Always pass an isolated `XDG_STATE_HOME` (and `--repo` to a throwaway repo for `pair`).
- **A corner operates as a Room: MEMBERSHIP is the authority, the branch is the shared artifact.** `DaemonService.corners` lists every corner the agent is a member of and `access` gates every corner write; `corner_facts.owner_agent_id` survives only as the historical "opened by" (`createdBy`, the phone's corner mark and card). `archiveCorner` alone stays with the opener (`assertCornerOpener`) — it is terminal for everyone's work; the merge webhook and a human close request still reach it. Each member helper cuts its OWN worktree from `origin/<feature_branch>` when GitHub has one (`materializeCornerWorktree`) and `corner-branch-sync.ts` rebases it onto that branch before every turn, raising `CornerBranchDivergedError` rather than clobbering a sibling's push. A message names its answerer: `MonolithCornerTurnLoop` answers a mention of itself, an unaddressed message and a check note go to the CARRIER (the member that answered last, opener by default), and only the opener kicks the objective off. An agent addressed in a corner it is not in gets a visible line, never silence — one of the three ordered reasons `PhoneService.noteUnansweredMentions` carries (see below). `github-operations.ts` posts PR/check facts and archives only from the merge webhook. A restored helper never re-announces `working` over existing PR/check lifecycle. **One check turn per changed server state, never per note** (`corner-checks.ts`): a completed check note starts ONE turn only when `getCornerRestoreState().lifecycle.checks` differs from the last turn's state; a checks-turn reply that only restates the notes is dropped (`isCornerStatusRestatement`), and a turn that called `open_corner` drops its own echo (`stripCornerOpenEcho`, `reply-sanitizer.ts`). **A corner's wake is not its own noise (C106):** `corner-wake.ts` is the ONE predicate for what wakes an intake loop — a corner's Room id IS the corner id, so its own draft/thought/retract/presence/activity/receipt publishes land on the channel it waits on and are ignored, consecutive wakes held `CORNER_WAKE_MIN_INTERVAL_MS` apart. ## Branch conventions

- **Corner agents own the GitHub workflow.** Finish means commit, push, `gh pr create`, print the URL, wait for the server checks-passed fact. With no human hold the agent merges with `gh`; the merge webhook archives and reaps the worktree.
- `fm/*` branches stack; check `gh pr list --json baseRefName,headRefName` before assuming a file is on `main`; `git branch -a --contains <commit>` finds the source branch.
- A cherry-pick off `feature/*` can drop a context-only declaration — `npm run typecheck` catches it. Stale `fm/*` merges conflict mostly on `relay-stack/web/dl/` artifacts — pick either, regenerate with `npm run bundle:beeline`.
